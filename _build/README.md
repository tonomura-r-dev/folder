# 提案資料のビルド手順（PC／スマホ共通）

LINE公式アカウント提案資料を、スクリプトから再生成するための一式です。
**スマホから claude.ai/code でこのリポジトリを開けば、同じ作業ができます。**

※ 業界別の資料（注文住宅・賃貸・EC など）はスキル `lineoa-industry` で作る。
ここは**FMT／ベースPPTXから直接ビルドする資料**の手順。

## ファイル構成

| パス | 中身 |
|---|---|
| `_templates/DYM_LINEOA_33p_base.pptx` | 33枚版のベース（DYMマスター入り・44枚） |
| `_templates/DYM_LINEOA_FMT.pptx` | 汎用版・9枚版のベース（DYM汎用FMT・36枚） |
| `_build/build_generic_lineoa.py` | **業界を絞らない汎用版（25枚）のビルド** |
| `_build/build_vivical_33.py` | 33枚版フル提案のビルド |
| `_build/build_vivical_9p.py` | 9枚版コンパクト提案のビルド |
| `_build/qa_render.py` | 全ページPNG化（QA用・Windows/Linux両対応） |

## 使い方

```bash
pip install python-pptx
python _build/build_generic_lineoa.py
python _build/qa_render.py "DYM_LINEOA_業界汎用_ご提案.pptx"
```

出力はリポジトリ直下、QA画像は `_qa/` に出ます。

## 業界汎用版（`DYM_LINEOA_業界汎用_ご提案.pptx`・36枚）

**FMTの構成をそのまま保った汎用版。** 業種依存の記述だけを外している。
ページは1枚も削っていない（殿村さん指示）。

**⚠️ FMTの罠：名前は「汎用FMT」だが、中身は人材(転職)業界の提案書が元になっている。**
FMTを流用するときは毎回ここを確認すること。

### 業種非依存に書き換えたページ（3枚）

FMTで転職者向けの設問・繁忙期になっていた3枚を、どの業種でも成立する「型」にした。
右上のバッジも「人材(転職)業界の例」→「業種別にカスタマイズ」に変更している。

- **p33 登録直後アンケート（5問）**：きっかけ／希望時期／予算／不安／他社利用経験
- **p34 年間の企画カレンダー（4枠）**：年度末・新年度／GW／下半期スタート／年末
- **p35 診断コンテンツ（4問＋4分類）**：検討の温度を測る設問と、追客方針の出し分け

ほかに表紙の「業界：○○」→「業界汎用版」、
業種を限定する語の中立化（定期購入→リピート／査定→見積／商圏→エリア）。

### ⚠️ 商談前に手当てが要るページ（11枚）

**ここは埋めないまま出せない。** ビルドすると同じ一覧がコンソールにも出る。

| ページ | 中身 | やること |
|---|---|---|
| 5, 6 | 検索広告CPCの推移／広告実績CVR | グラフが未挿入。業界のCPC・実績CVRを貼る |
| 7, 8 | ニーズ調査（シーズナリティ／前後検索） | 転職KWのGoogleトレンド画像＋「あああ」。業界KWで撮り直す |
| 9, 10 | 他社配信アカウント／他社分析 | 「すうじ」「ロゴ」のダミー。競合の実数値・キャプチャに差し替え |
| 12〜16 | 具体企画のブレスト | 社内メモのまま。企画案を書くか、商談では飛ばす |

※ 5,6 は注文住宅の記憶メモにある「S5/S6は運用に純化するなら削除候補」と同じ2枚。
※ 競合の友だち数はクラウドから取れない（`page.line.me`／`lineoa.jp` がegressブロック）。**PC側で取得すること。**

軽い版が要るときは `build_generic_lineoa.py` の `DROP` にこの11枚を入れれば25枚になる
（スクリプトのコメントに番号を残してある）。

### 業界別に出すときの差し替えチェックリスト

1. 表紙の「業界汎用版」→「業界：不動産」のように業種名を入れる
2. 上の11枚に業界データ（CPC・トレンド・競合キャプチャ）を差し込む
3. 「〇〇」表記を実際の商材名に置換（価格帯・特典名・トレンドレポート名など）
4. p33〜35（アンケート／年間カレンダー／診断）を、その業種の言葉に寄せる

## 修正するときはここを触る

- **文言・数値**：`build_vivical_33.py` の各 `# ===== Slide NN =====` ブロック
- **スライドの並び／採否**：先頭の `ORDER`（ベース44枚の何番をどの順で使うかの指定）
- **配色**：先頭の定数（`TNAVY` タイトル紺 / `NAVY` 打ち手紺 / `RED` 課題赤 / `INK` 本文）

## 落とし穴（踏んだので書き残す）

1. **`put_text()` は必ず `reset_tf()` を通す。** 既存スライドのシェイプにそのまま書くと、
   元のテキストへの「追記」になって文字が混ざる（例：「ヒアリングの上Meta広告のみ確定」）。
2. **スライドの追加はしない。** ベースから削除＋並べ替えだけで構成する。
   python-pptx でスライドを新規追加すると、パート名の重複で壊れることがある。
   新しい内容が要るときは、使わないスライドの中身を `clear_slide()` して作り直す。
3. **流用スライドの業種残骸に注意。** ベースは別業種（EC・人材）の提案書なので、
   「定期購入・クロスセル」等の文言が残っていないか毎回確認する。
4. **QAのフォント。** クラウド（Linux）にメイリオが無い場合、代替フォントで描画されるため
   文字あふれの判定がズレる。**最終確認はPCの PowerPoint COM で行うこと。**
