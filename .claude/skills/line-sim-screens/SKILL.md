# スクショからシナリオ案を作る（line-simulator）

詳しい決まりは `line-simulator/docs/AI_WORKFLOW.md`。データの形は `line-simulator/docs/DATA_MODEL.md`（§3〜§5・§10）。ここでは手順だけを書く。

## 守ること（いちばん大事）

- **写っているもの＝確認済み（observed）**：文面・メニューやボタンの文字は写っているとおりに。`prov.source` に `screenshot:<ファイル名>` を必ず書く。
- **写っていないもの＝AI推定（inferred）**：分岐の条件・タグ・配信の日時・停止条件・アンケートとタグの対応・CV・シナリオのつながり・ペルソナと台本。`prov.rationale` に根拠を必ず書く。
- **`approved` は付けない**（承認は人だけ）。
- 推定を「既存アカウントで実際に動いている仕様」として書かない・言わない。
- **固有名詞は伏せる**：会社名・店名・人名・電話番号・URLは `〔店名〕` 等に置き換え、`brand.companyName` は「〇〇サンプル（仮）」。伏せたら `source` に「固有名詞は伏せ字」。
- `project.json` を直接書き換えない。出すのは差分ファイルだけ。
- スクショは `projects/<案件>/screenshots/`（リポジトリに入らない）。コミットしない。

## 手順

1. 案件フォルダ名を確かめる（無ければ編集ツールで作ってもらう）。`line-simulator/projects/<案件>/screenshots/` の画像をすべて Read で見る。
2. **見えたもの一覧**を作る：スクショごとに、写っている文字（書き写し）・画面の種類（リッチメニュー／トーク／アンケート／Webページ／ポップアップ）・ボタン。
3. `projects/<案件>/project.json` を読み、いまあるIDを確かめる。`basedOn` には次で出る値を入れる：
   `node -e "import('./packages/engine/src/index.ts').then(m=>console.log(m.projectHash(JSON.parse(require('fs').readFileSync('projects/<案件>/project.json','utf8')))))"`（line-simulator フォルダで実行）
4. 差分を組み立てる。
   - 1つの提案＝人が採る／採らないを決められる1つのまとまり（文面1つ・メニュー1つ・シナリオ1本〈ノードと線ごと〉）。
   - 配列には `"/messages/-"` のように1件ずつ追加。既存の部品を写っている内容で直すときは `replace`（例 `/messages/0`、`/brand`）。
   - ID は種類ごとの接頭辞（`msg_` `tag_` `cv_` `route_` `flow_` `n_` `e_` `btn_` `cell_` `sv_` `q_` `c_` `page_` `ar_` `p_` `nar_`）。ノードIDとボタンIDは案件全体で重ならないように。
   - ノードの位置は縦に並べる（x=0、y を 150 ずつ）。分岐の先は x を ±260 ずらす。
   - シナリオ1本の中で、写っている文面のノードは observed、つながり・待機・分岐は inferred とノードごとに付ける。
   - デモで流せるよう、ペルソナ（2〜4人）と台本を推定として足す。台本の時刻は Day 0 の 10:00（600）以降。
   - 説明文（narration）も推定として2〜4件足すと、デモで説明カードが出る。
5. `projects/<案件>/patches/<YYYYMMDD-HHmm>_<短い英数字>.json` に保存する（ファイル名は英数字・`-`・`_` のみ）。
6. line-simulator フォルダで `npm run patch:check -- <案件> <ファイル名>` を流し、OK になるまで直す。
   「AI推定が承認されていません」は正常（件数が出るだけ）。それ以外の重大エラー・当たらない提案は直す。
7. 報告する（短く）：
   - 見えたもの（スクショごと）
   - 推定したもの（根拠つき）と、**特に確かめてほしい点**
   - 次の操作：「編集ツール → 案件を開く → AI提案（スクショから） → 提案ファイルを選ぶ → 取り込む → 承認」
