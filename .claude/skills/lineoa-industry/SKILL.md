# 業界別 LINEOA提案 ジェネレーター

**インプットは業界名のみ。** 確認の往復をせず、業界知見で前提を埋めて一気に作り切る。
置いた前提は必ず報告の冒頭（または末尾の要確認リスト）に明示する。

## 1. 内部推論エンジン（業界名から自動補完する5要素）

| # | 要素 | 具体化する内容 |
|---|---|---|
| ① | ペルソナ・顧客属性 | 年齢／性別／購買決定権（本人・配偶者同席・親）／世帯年収／行動特性（SNS・検索・来店） |
| ② | 数値水準 | 平均顧客単価／想定LTV／業界平均Web CPA／推奨広告予算レンジ |
| ③ | 前後検索KW | **15日前**＝漠然とした情報収集（費用相場・失敗例・時期・やり方）／**15日後**＝業者名・口コミ・評判・解約/保証の不安・比較 |
| ④ | 心理的ハードル | なぜWEBフォームで離脱するか（押し売り・電話営業への恐怖／情報過多の迷い／個人情報を出す抵抗／今すぐでない後ろめたさ） |
| ⑤ | 最適なLINE施策 | 診断フック（30秒〇〇診断・1分費用シミュレーター）／タブ切替リッチメニュー3種／14日ステップ配信 |

### CV3段は必ず自分で設計する

`①低ハードル（軽CV）→ ②中間行動（主CV）→ ③最終CV/LTV`

例：学校＝資料請求→OC予約→出願／買取＝査定予約→成約→リピート／ブライダル＝フェア予約→来館→成約。

**どれを主CVに置くかで主施策が変わる。** 軽CVが取れる業種＝離脱防止が主役／重CVが遠い業種＝ナーチャリングが主役。

## 2. コアストーリー（起承転結）— 全スライドをこれに紐づける

1. **【マクロ市場の厳しさ】** 広告費は上がり続け、AI検索（AIO）時代でWEBからの直接申込は急減している
2. **【エンドユーザーの深層心理】** ユーザーは「押し売りされたくない」「失敗したくない」。いきなり氏名・電話を入れるのを嫌がる。前後検索データを見ても、調べる前も後も不安を抱えている
3. **【LINEによるCX改善】** だから心理ハードルの低いLINEを挟み、「診断」と「透明性のある情報提供」で不安を先回りして解消する顧客体験が要る
4. **【クライアントの売上成果】** 納得して選ぶ仕組みだから離脱が消え、来店/商談率（歩留まり）が改善し、最終売上が伸びる

> 主語は常に**クライアントのKPIとエンドユーザー体験**。自社が売りたいプランに寄せない。

## 3. 競合データの取り方（推測で書かない）

友だち数・運用実態を憶測で書くのは**禁止**。以下の順で実データを取る。

1. **`lineoa.jp/others/<アカウント名>/`** — 友だち数・増加数・配信数・リッチメニュー構成まで見える。**ただし第三者サイトなので「当たり付け」専用。この数値をスライドに載せない**（→[[feedback_official_sources_only]]）
2. **`page.line.me`** — **スライドに載せる数値はここ（公式）か実機で取り直す**。自アカウントの数値は `_accountHeadSubText` 直後。**「おすすめ」欄の数値を拾わない**
3. **取得日を必ず併記。** 値が古ければ「提案前に再取得」と注記する
4. 競合選定は**知名度優先（大手中心＋運用が特徴的な中堅1〜2）で5〜10アカウントを自動選定してよい**（本スキルで事前承認済み）。ただし選定リストは冒頭に明示し、**実名掲載の最終OKは要確認リストの上司確認項目に必ず入れる**
5. 実機スクリーンショットは人が撮る前提で**差込枠**を用意し、撮影対象を要確認リストへ（調査用の捨てアカウントで実施するよう添える）

### 運用の型は3〜4分類して見せる

- **診断ドリブン型**（診断で属性取得→検討段階別に出し分け）
- **相談カウンター型**（有人相談・店舗送客が主。配信していないことが多い）
- **特典・会員型**（限定特典で友だち化）
- **カタログ型**（商品/会場一覧・予約が中心）

型の差が「友だち数」と「増加率」のどちらに出ているかまで書くと刺さる。
※ **配信数と増加率の関係は相関。因果と言い切らない。**

## 4. LINEヤフー公式事例の扱い

- 公式事例（`lycbiz.com/jp/case-study`）は**業界によっては1件も存在しない**（例：結婚式場そのものはゼロ）
- 無ければ**正直に「該当なし」と報告**し、①近接業界（購買構造が近い）で補って明記するか、②公式データで代替する。**捏造しない**
- 代替に使える公式データ：LINE国内月間利用者数（1億人突破・2025年12月末）／メッセージは受信直後 約2割・3〜6時間で約5割・**当日中に約8割が開封**
- 「開封率60〜80%＝メルマガの3〜4倍」は**公式値ではない**。業界平均・自社実績としてラベルを分ける
- 「LINE経由で来店率40〜50%改善」は**DYM支援実績**であって公式値ではない。出典を混ぜない

## 5. 成果シミュレーションの型

Before（Web広告のみ）／After（Web広告 × LINE OA）を1表で。**広告費は据え置き、LINE運用費だけ足す**のが説得力の肝。

| 指標 | Before | After |
|---|---|---|
| 投下計（広告費＋LINE運用費） | 広告費のみ | ＋LINE運用費 |
| LP流入 × LP CVR | 現状 | **変えない** |
| 広告経由のCV | 現状 | 同数 |
| LINE友だち化（離脱防止） | ― | 流入の◯%（★仮置き） |
| LINE経由のCV | ― | 友だちの◯%（★仮置き） |
| CV合計／獲得CPA | | |
| **来店・商談率（歩留まり）** | 現状% | **改善後%** |
| 来店数／来店CPA | | |
| 成約／売上／**粗利** | | |

**必ず添える解説3点**
1. **LP CVRは動かしていない** — 触るのは「LPから落ちた後」と「予約が入った後」の2箇所だけ
2. **効くのは"率"であって母数ではない** — CV増より歩留まり改善のインパクトが大きい。広告費を増やさず改善できる区間＝費用対効果が最も高い
3. **粗利で締める** — 売上ではなく1件あたり粗利で語ると経営層の判断軸に乗る

**仮置きは3つまで**（例：友だち化率／友だち→CV転換率／成約率）。★で明示し、出典のある数値（単価・粗利・業界CPA）とは分けて書く。

## 7. 鉄則（違反＝差し戻し）

- **出典のない数値を書かない。** 業界指標／自社実績／仮置きを混ぜず、ラベルを分ける
- **競合は実名を出すなら実データで。** 未確認なら「仮説」バッジ、または破線の差込枠にする
- 1枚1メッセージ／1カード3〜4行／1行20〜25字
- メイリオ／3色（ネイビー・炭黒・オレンジ。LINEグリーンはUI部分のみ）／DYMマスター維持
- 相関を因果と言い切らない
- 最後に必ず **【要確認リスト】** を付ける。3分類：**① 置いた前提（★）／② 社内・上司確認が要るもの／③ 人が集める素材（スクショ等）**
- 要求する情報の種類を増やさない。②③は下の5種に限定する
  1. Googleトレンドのスクショ（比較KW4つを指定）
  2. 上司確認3点（社内広告実績のCV地点別CPC/CVR/CPA／出典未確定数値の扱い／競合・事例の実名掲載OK）
  3. LINEヤフーの前後検索データ（対象KW指定）
  4. 競合の友だち追加調査（トーク配信の中身）
  5. 事例ストック調査結果／上司共有資料の反映

## 8. PPTXを作る場合のQA（モードB・C共通）

1. **PowerPoint COMで全枚PNG化 → 目視**（文字切れ・折返し・白文字・重なり・脚注のかぶり・画像の切れ）→ 修正 → 再QA
2. `validate.py <deck> --original <FMT>` が PASS
3. スライドサイズは **9906000 × 6858000 EMU** 固定（変更禁止）
4. 見出しband は**2行以内**（3行でタイトルに被る）／脚注は **y=17.35cm**（17.9cmはフッター帯に重なる）
5. 保存前に対象ファイルがPowerPointで開かれていないか確認（PermissionError回避）
6. 原本FMT・完成見本は**編集禁止**。必ずコピーして作る
