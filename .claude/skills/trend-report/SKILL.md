# トレンドレポート作成スキル

殿村さん（DYM）が毎月作る社内向け資料。「LINE公式アカウント 媒体最新情報 ◯月 トレンドレポート」。
LINEヤフー社の更新情報（テキストの箇条書きやPDF）を、DYMの実営業資料と同じトンマナのPPTXに変換する。

## 全体の流れ（1ヶ月分）

1. **ネタ出し**：殿村さんが「媒体最新情報」の一覧（トピック名＋概要＋出典URL、TSV/表形式が多い）を貼る
2. **構成案を作る**：全トピックをスライド構成（表紙／目次／各トピック4区分）に整理し、対象業界・フェーズ・フラグ等の元データにない項目は空欄のまま出す（**実データを見ずに推測で埋めない**）
3. **PPTX化**：`_build/trend_report_engine.py` を使ってFMTトンマナでPPTX生成
4. **アジェンダを上長確認に回す**：殿村さんが上司に9件などのリストを見せ、採否コメントをもらってくる。「先月やった」「期限切れ」「優先度低いので後ろ／除外」等の指示をそのままアジェンダに反映
5. **PDFで肉付け**：各トピックについてLINEヤフー社の詳細資料（PDF）が送られてくるので、4区分（概要・変更点／料金体系・出稿条件／スケジュール・導入フロー／注意点・影響）に該当箇所を振り分けて追記
6. **毎回 commit & push、ファイルを送る**

途中で何度もPDFが送られてくる・アジェンダが変わる・同じPDFが重複して再アップロードされる、というのが通常運転。**慌てず現状のTOPICS構造を1件ずつ更新していけばよい。**

## ファイル構成

| パス | 役割 |
|---|---|
| `_templates/DYM_LINEOA_BUFFF_FMT.pptx` | 実際の営業資料そのもの。トンマナの正本 |
| `_build/trend_report_engine.py` | 共通エンジン（レイアウト・配色・FMT継承ロジック）。**月をまたいで使い回す。基本触らない** |
| `_build/build_trend_report_YYYYMM.py` | 月次データ（TOPICS_LIST・TOPICS・OUT・MONTH_LABEL）だけを持つ薄いスクリプト |
| `LINEOA媒体最新情報_YYYY年M月トレンドレポート.pptx` | 出力（リポジトリ直下） |

### 新しい月を始めるとき

`_build/build_trend_report_202609.py` を同じ月数字違いでコピーして、`MONTH_LABEL` / `OUT` / `TOPICS_LIST` / `TOPICS` を書き換えるだけ。`trend_report_engine.py` は触らない（レイアウトが変わるのは殿村さんから明示的に指示があったときだけ）。

## トンマナの正体（触るときに必ず思い出すこと）

**`_templates/DYM_LINEOA_FMT.pptx`（提案書系のFMT）とは別物。** トレンドレポートは `DYM_LINEOA_BUFFF_FMT.pptx` を使う。最初に前者のトンマナで作って「トンマナが全然違う」と指摘されたことがあるので混同しない。

- ヘッダーのネイビー角アイコン・区切り線・DYMロゴ（画像）・フッターの著作権表記／ページ番号は、**FMTのスライドレイアウト側に定義されていて、`clear_slide()` でスライド自身のシェイプを消しても継承表示される。** 自前で描画しない・する必要がない（2026-09 に `test_inherit.jpg` で検証済み）。
- コピー→必要枚数だけ残す→`clear_slide()`→中身を作り直す、という経路（`build_special_plan.py` と同じ）。**python-pptx でのスライド新規追加はしない**（壊れる。CLAUDE.md参照）。
- 配色（FMT実測値）：
  - タイトル／見出し：`002060`（TITLE_NAVY）
  - セクションチップ塗り：`10253F`（CHIP_NAVY）
  - 本文：`343434` / メタ情報：`494848`
  - 強調・注意：`FF0000`（純赤、FMT内で実際に使われている色）
  - ボックス塗り（メインメッセージ等）：`F2F2F2`
  - 枠線：`D9D9D9`
- フォントは全部メイリオで統一（`set_font_all` が a:latin/a:ea/a:cs 全部に適用）

## 1トピックのスライド構成

- ヘッダー直下にトピックタイトル（`page_title`、太字17pt、ネイビー）
- メインメッセージ：1〜2文の要約を薄グレー箱で強調（`LIGHT_BOX`）
- 本文は2×2の4区分ボックス固定：**概要・変更点／料金体系・出稿条件／スケジュール・導入フロー／注意点・影響**
  - 箱ごとに項目数で自動フォント調整（4件以下10pt→5件9pt→6件以上8.5pt。`topic_slide()` 内で自動）
  - 情報がない区分は「－」で明示する（空白のまま放置しない）
- 左下に出典URL（`source_line`、極小グレー）
- 目次スライドの各項目は番号チップ＋テキスト1行（`agenda_slide`）
- 表紙は `cover_slide(slide, month_label)`。`month_label` は `"2026年9月"` のように「年」区切りで渡す（内部で年と月を分けてタイトル・バッジに使う）

過去に「対象業界／フェーズ／代理店限定／展開禁止」のメタ行をヘッダー直下に置いていたが、**使わないとの指示で全廃した。** 今後もこの4項目の帯は付けない。

## データの集め方・落とし穴

- **`workers-hub.box.com` はこの実行環境からegressブロックされていて中身を見られない。** 出典URLとして記載するだけにして、内容確認は殿村さんからPDF／テキストで送ってもらう
- PDFは同じ内容が複数回・別ファイル名で再アップロードされることがある（ページ数や容量が完全一致していれば重複とみなしてよい）。**新しく届いたPDFが本当に新規情報かどうかは、既存TOPICSの該当トピックと見比べて判断する**（今回は「プロモーションスタンプ」の新PDFだけ本当に新情報だった、という前例あり）
- 大きいPDF（1ファイルが数MBや十数ページ超）は `Read` ツールに `pages` パラメータが必須になる。まず先頭数ページで構成を把握してから必要な範囲を追加で読む
- PDFの内容を4区分に振り分けるときの目安：
  - **概要・変更点**：何がどう変わるか（AS-IS→TO-BEがあれば必ず入れる）
  - **料金体系・出稿条件**：金額・通数・掲載期間など。無ければ「該当なし」
  - **スケジュール・導入フロー**：リリース日・申請〜掲載までの営業日フロー
  - **注意点・影響**：FAQ・キャンセル規定・影響範囲・要確認事項
- 上長確認で「除外」「書き直し」「優先度低いので後ろ」等の指示が出たら、`TOPICS_LIST` と `TOPICS` の両方を並び替え・削除する（片方だけ直して目次と中身がズレる事故に注意）

## ビルド〜納品の手順

```bash
python3 _build/build_trend_report_202609.py
```

出力後は必ず見た目を確認してから渡す（文字あふれ・4区分ボックスからのはみ出しがないか）。

```bash
rm -f "LINEOA媒体最新情報_2026年9月トレンドレポート.pdf"
soffice --headless --convert-to pdf "LINEOA媒体最新情報_2026年9月トレンドレポート.pptx"
python3 -c "
import fitz
doc = fitz.open('LINEOA媒体最新情報_2026年9月トレンドレポート.pdf')
for i, page in enumerate(doc):
    page.get_pixmap(dpi=130).save(f'/tmp/.../slide{i+1:02d}.jpg')
"
```

生成したJPGをReadツールで確認し、はみ出しがあれば `topic_slide()` のフォント自動調整の閾値を疑う（項目が長文すぎる場合は文言を削る方を優先。レイアウト側は基本いじらない）。

`libreoffice-impress` と `poppler-utils`（pdftoppm用。使わなくてもPyMuPDFでフォールバックする）が入っていないことがあるので、無ければ `apt-get install -y libreoffice-impress poppler-utils` を入れる。

確認できたら commit & push し、`SendUserFile` で殿村さんに渡す。**社内配布物なのでコミットして問題ない**（クライアント個別の金額等が入る資料とは違う）。
