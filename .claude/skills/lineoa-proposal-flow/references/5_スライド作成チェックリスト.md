# スライド作成チェックリスト（殿村さんの決定事項・2026-09-30 時点）

資料（PPTX）を作る・直すときは、**納品前にこの一覧を上から順に確認する**。
出典は CLAUDE.md の記憶メモ。新しく決まったことは CLAUDE.md とこのファイルの両方に足す。

## 言葉・文体
1. **文末は言い切り**（です・ますを付けない）。例：「〜を図る」「〜が最適」「〜を後押し」「〜可能」。
   先方への頼み・申し出も「ご相談可能」「対応可能」の形。**LINEの訴求文（ユーザーに見せる文言）はそのまま**
2. **先方にそのまま出せる言葉**で書く。社内の会話の言い回しを入れない（「人」→「方」、「山」→「ピーク」、「運ぶ」→「つなげる」）
3. 使わない言葉：「スコープ」「赤字」（色は「赤い文字」）「近い業種」、自分で作った略語（「8F」→「8フェーズ」）

## 数字
4. **SIMの数値は圧縮しない**。合計・平均・幅（〇〜〇）にまとめず、月ごと・アカウントごとにそのまま出す
5. **小数は出さない**。件数・金額・CPA・CPOは整数（円単位）。按分は端数の大きい順に繰り上げ、合計をSIMに合わせる
6. SIMのCVRは 0.3〜1.0% 前後
7. CVの定義は資料とSIMで揃える（CPAに入れない数は合計CVに足さない）
8. 根拠（出典URL）のない数字は載せない。2つのAIで食い違ったら公的統計の方

## 見た目
9. **字体はすべてメイリオ**（"Meiryo"表記・指定なしも直す。latin→ea→cs の順）。やり方は `_build/patch_yaruki_v32_iikiri.py` の末尾
10. 良い数字を赤い文字で強調しない
11. 前後検索：タイトルは **前後検索「KW名」**。色分けは結論と同じ分類・同じ数の色、凡例は画像の上。
    分析はチェングロウスの型（カーディーラー型＝LINE追加の黄緑の帯＋追加率を上げるコンテンツ＋登録後の日別コンテンツ／工場求人ナビ型＝検索前・当日・後の3枚＋配信の順番）
12. 出典の行は出典だけ（言い訳・社内の注記を入れない）
13. 画像（画面イメージ・イラスト）は作らない。生成用プロンプトをコードブロックで出し、資料には差し込み枠だけ置く
14. 表の行・列を複製したら a16:rowId / a16:colId を振り直す（PowerPointでだけ青帯になる）
15. 余白が大きいときは、文字と図形を大きくして埋める（無駄な余白を残さない）

## 進め方
16. **殿村さんが送り直したファイルを必ず元にする**。付けた名前・シート名は消さない
17. 決まったことは関係するページ・SIMのすべてに一度に反映し、反映先を一覧で返す
18. ページの分類・見出しは1枚ずつ「提案のどこを支えるか」を確認してから決める（前に自分で付けたラベルを流用しない）
19. 新しいFMTに合わせるかは毎回確認する（勝手に合わせない）
20. 施策のビジュアル化は本資料と別ファイルで ①〜④ を1枚ずつ（表紙なし）。原本は `_templates/DYM_LINEOA_施策ビジュアルFMT（①〜④）.pptx`
21. 個別提案のアジェンダは「業界の課題 → だからこの施策」の型
