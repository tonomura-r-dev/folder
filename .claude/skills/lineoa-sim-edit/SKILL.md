# LINEOA SIM 編集

既にあるSIMファイルを**Claudeが直接書き換える**ときのスキル。新規作成は `lineoa-sim`（表の提示まで）。

## 鉄則

- **編集前に必ずコピーを取る。** 上書き保存すると式は二度と復元できない（長い式は読み出し時に切れるため、記録からの復元も不可）
- 提出用のきれいな名前のファイルを直接触る場合、`_bk` を scratchpad に退避してから作業
- **関数はむやみに触らない。** 入力セル（値）と係数セル（P列）で足りるなら、そちらで調整する
- 変更したら必ず再計算して検算し、**変えたセルだけを見せる**（スマホで確認されることが多い）

## 1. FMT行構造マップ（毎回探し直さない）

列：`D`＝現状／`E`〜`J`＝1〜6か月目

### 与件（上部）
| セル | 内容 |
|---|---|
| C6〜C9 | CV地点名（購入・資料請求・来場予約 等） |
| D6〜D9 | 成果単価 |
| H6 | UU全体 |
| H7 | UU（うち広告） |
| H8・H9 | 現状の月間CV（別施策分） |
| K6 | 想定顧客リスト（通知メッセの母数） |

### トグル（15〜19行）TRUE/FALSE
| 行 | 施策 |
|---|---|
| 15 | CPF |
| 16 | 離脱防止 |
| 17 | サンクスLINE誘導 |
| 18 | 通知メッセージ_CV |
| **19** | 通知メッセージ_既存リスト → **どこからも参照されていない飾り** |

### 友だち増分（20〜27行）
| 行 | 内容 |
|---|---|
| 20 | CPF増分（式が通らずベタ打ちすることが多い） |
| 21 | 離脱防止増分 |
| 22 | サンクス増分 |
| 23 | 通知メッセ増分 |
| 24 | 月間増分合計 ＝ SUM(20:23) ＋ H7×P14 ＋ (H6−H7)×P13 |
| 25 | ブロック率 |
| 26 | 友だち数（累積） |
| 27 | アクティブ数 ＝ 26×(1−25) |

### 配信〜CV（28〜39行）
| 行 | 内容 |
|---|---|
| 28 | 企画投稿数 |
| 29 | 企画投稿からの流入 |
| 30 | ステップ配信本数 |
| 31 | ステップ配信からの流入 |
| 32 | **配信数** ＝ 27×28×P22 ＋ 27×30×P26 |
| 33 | 想定Click数 |
| 34〜37 | CV（地点別・**ベタ打ちが基本**） |
| 38 | CV合計 |
| 39 | CVR ＝ 38÷33（**Click基準**。配信数基準ではない） |

### 費用ブロック
| 行 | 内容 |
|---|---|
| 41〜49 | **成果報酬プラン**。43＝固定費計／**47＝CPA想定（単月）**／48＝成果報酬費用／49＝総計コスト |
| 52〜59 | **コンサルプラン**。59＝総計 |
| 63〜70 | 費用内訳（下表） |
| 71 | コスト総計 |
| 73・74 | 追加通数・想定単価（従量課金の計算用） |

| 行 | 費目 |
|---|---|
| 63 | 従量課金 `=MAX(0,15000+(配信数−30000)*2.75)` |
| 64 | 離脱防止 |
| 65 | サンクス誘導 |
| 66 | アカウント費 `=IF(配信数<5000,5000,15000)` ← **開設費ではなくLINE社の月額プラン費** |
| 67 | コンサル費①（月次） |
| 68 | コンサル費②（初期ショット） |
| 69 | 機能拡張 ← 通知メッセのツール費・CPF費用の置き場 |
| 70 | APIツール費 |

### 係数（P列）
| セル | 意味 |
|---|---|
| P13 | 非広告UUのベース友だち化率 |
| P14 | 広告UUのベース友だち化率 |
| P16・P17 | 離脱防止の掛け目（広告UU側／非広告UU側） |
| P20〜P22 | 企画配信の係数 |
| P24〜P26 | ステップ配信の係数 |
| P34 | 総合係数（Q30〜Q33のTRUE/FALSEから算出） |
| Q22・Q26 | 4〜6か月後の逓減係数（0.8） |

## 2. ★「SIM考え方」シートは本体から参照されていない

独立したメモで、**本体の式と全施策でズレている**。根拠を聞かれてこのシートを見せると事故る。

| 施策 | 考え方シート | 本体の式 |
|---|---|---|
| 離脱防止 | 0.085 × 0.08 ＝ 0.68% | 0.08×0.08＝0.64% ／ 0.12×0.12＝1.44% |
| サンクス | 0.9 × 0.35 ＝ 31.5% | 15% |
| 通知メッセ | 追加率 **0.2（20%）** | **0.1×0.15（1.5%）** |

**離脱防止**はECの前例（田苑酒造・名古屋デザテク）に合わせて意図的に変えた記録がある。
**サンクスと通知メッセは変えた理由が不明。** 使うなら考え方シート側（社内の型）に戻すほうが説明できる。

## 3. Excel操作の作法（COM）

### PowerShellスクリプトの書き出し
日本語を含むなら **UTF-8 BOM必須**。Writeツールの出力はBOMなしなのでShift-JIS誤読でパースエラーになる。
Pythonで `io.open(path, 'w', encoding='utf-8-sig')` を経由して書き出す。

### ロック対処
```powershell
if ($wb.ReadOnly) { Write-Output "LOCKED"; $wb.Close($false); $xl.Quit(); exit 1 }
```
**LOCKEDが出たらまず孤児プロセスを疑う。** COM操作の残骸が `MainWindowTitle` 空のExcelプロセスとして残り、ファイルを掴んでいることがある。
```powershell
Get-Process EXCEL | Where-Object { [string]::IsNullOrWhiteSpace($_.MainWindowTitle) } | Stop-Process -Force
```
ウィンドウなし＝ユーザーが開いているものではないので落として安全。それでもLOCKEDならユーザーに閉じてもらう。

### 後始末
```powershell
$wb.Save(); $wb.Close($true); $xl.Quit()
[System.Runtime.InteropServices.Marshal]::ReleaseComObject($xl) | Out-Null
```
ReleaseComObjectを省くと孤児プロセスが残る。

### シート名の変更
**COMなら他シートの参照が自動追従する。openpyxlでやると壊れる。** 名前の入れ替え（A→B、B→A）は一時名を経由する。

### 再計算
openpyxlは式を計算しない。**編集後は必ずCOMで開いて `CalculateFullRebuild()` してから保存**しないと、読み出したときに古いキャッシュ値が返る。

### 参照の一括置換
```powershell
$ws.Cells.Replace("旧シート名", "新シート名", 2, 1, $false)
```

## 4. よくある編集タスク

### シートを強い順に並べ替える
**番号順＝強い順が社内ルール。** ①が最も強いシナリオ。
```powershell
$wb.Worksheets.Item("名前").Move($wb.Worksheets.Item(1))            # 先頭へ
$wb.Worksheets.Item("B").Move([Type]::Missing, $wb.Worksheets.Item("A"))  # Aの後ろへ
```

### UU・母数を変える
`H6`（UU全体）と `H7`（うち広告）。**広告UUを分けない場合は H7=0**。
※H7=0にすると全量が「非広告UU側」の係数（P17・P13）で計算される。広告UU側より係数が高く設定されていることが多いので、**友だちが増える方向に動く**点に注意。

### CVRを指定値に合わせる
CV行（34〜37）はベタ打ち。**配信数（32行）× 目標CVR** で計算して入れる。
- 標準レンジは**配信数基準で0.3〜1%**
- 39行のCVRは**Click基準**なので別物（Click基準だと13〜20%になることがある）
- 母数が小さくてCVRを盛るしかない場合は、**CVRではなく母数側（CPF・通知メッセ）を足して解決する**

### 通知メッセを入れる
1. `K6` にリスト件数、18行のトグルをTRUE
2. E23の式を**月ごとに分ける**（既定の式は毎月同じだけ加算するので、一斉送信が6回カウントされる）
   - 初月：`SUM(H8:H9)*0.7*0.3 + K6*0.2`
   - 追撃月：`SUM(H8:H9)*0.7*0.3 + K6*0.8*0.1`（未反応80%に半分の追加率）
   - その他：`SUM(H8:H9)*0.7*0.3`
3. 69行にツール費（月8万）、70行に通数課金（送信数×7円）を月別で置く
4. 初期費用は D70 に10万

### 12か月列（比較シート）
比較シートは「実装前／3か月／6か月／12か月」の4列がFMT標準。
12か月は**3→6か月の伸び率を0.95・0.9で減衰させた推計**（`=E6*(E6/D6*0.95)+E6*(E6/D6*0.9)`）。
**初月に母数が一気に入る設計（通知メッセの一斉送信など）だと3→6の伸び率が鈍って推計が壊れる。** その場合は12か月列を消すか、手で置く。

## 5. 数値の相場

### 通知メッセージ
| 項目 | 値 | 出典 |
|---|---|---|
| 費用 | 初期10万＋月8万〜＋**通数7円/通** | 提案資料の実物（BUFFF費用表の「初期20万/月60万」とは別物。**実物スライドを優先**） |
| 友だち追加率 | **20%**（社内の型＝考え方シート） | SIM考え方 B21 |
| 同・公開実績 | **約30%**（受け取った人の3人に1人） | アパレルEC nairo／ソーシャルPLUS |
| 同・経路シェア | 新規友だちの44%が通知メッセ経由 | 工具通販ビルディ／同上 |

**電話番号あての機能。メールアドレスでは打てない。** 母数は「電話番号を保有している顧客数」であって、メルマガリスト件数ではない。

### 離脱防止ツール
**初期1.5万＋月3万**（BUFFF p27・p28。川本さん確認と一致）。
※同資料 p36・p37 には「初期1万／月1万〜」と別の数字があるが、**提案に載せるのは p27・p28 側**。

### サンクスLINE誘導
初期5万＋月3万〜。追加率は本体式15%／考え方シート31.5%。

### 母数を4段階で区別する（通知メッセの設計時）
1. 累計の会員登録数
2. 累計の購入者数
3. **現在アクティブな顧客**
4. 直近の休眠者

**通知メッセを打つ意味があるのは3＋4。** 1に全件送ると通数課金だけで数十万〜百万円規模になる。
トリガー配信（解約期限の◯日前に該当者だけ）にすれば通数は月100通程度まで落ちる。

## 6. 検算と報告

編集後は必ずこれを出す。

```
シート順／友だち数／配信数／CV/月・半年計／CV÷配信数／単月CPA（47行）／初期＋月次＝総額／累計CPA
```

**単月CPAと累計CPAを区別する。** 累計は初期費用が丸ごと乗るので高く出る（例：単月8,129円 vs 累計10,432円）。
提案では**単月で見せる**——右肩下がりで既存CPAに収束する絵が描ける。初期は別建てで明記する。

**報告は変更したセルだけに絞る。** 全体を貼らない。スマホで見られることが多いので、表は3〜5行に収める。
