# 配信企画案スキル（運用中のLINE公式アカウント）

殿村さんの3案件の「毎月の配信企画案」を、毎回同じ手順・同じルールで出すためのスキル。
ルールの出どころは CLAUDE.md の記憶メモ（2026-08-31〜）。**ここと CLAUDE.md が食い違ったら、日付の新しい方を採り、両方を直す。**

## 0. 最初に読むもの
1. 案件ファイル（1つ）：`clients/inkart.md`／`clients/norst.md`／`clients/house.md`
2. シートの列と書き方：`sheet_columns.md`
3. `_memory/INDEX.md` のその案件の行と、案件ファイルの「最新の記録」に挙げたファイル（先月の企画案・数値分析）

ハウス食品は**ステイ中**（2026-10-01）。再開の指示があるまで企画案を出さない。

## 1. 進め方（2段階。いきなり全文を出さない）

### 段階1：枠を出して認識を合わせる
- 出すもの（表）：No.／配信日（曜日）／企画案／狙い概要／ターゲット／この回にした理由（1行）
- 決め方は「2. 組み方」
- 未確定の値（割引率・期限・商品の仕様・先方の予定）があれば、ここで聞く。〔 〕のまま先に進まない
- 足りない材料は「足りないもの」として一覧で出す。今使うのか、いつ使うのかも書く
- **ここで止まって、殿村さんのOKを待つ**

### 段階2：OKが出たら中身を書く
- **本文を出すときは、各回の意図を必ず添える**（誰に／何を伝えるか／どう動いてほしいか。2026-10-01 殿村さん「意図がないとどういう訴求かイメージがわからない」）
- 順番：テキスト（＋アイテム名）→ OK → 備考・バナー参考（画像生成プロンプトは全文）→ URL・ga_*・GA_URL
- 1本ずつ、シートの列順で出す（`sheet_columns.md`）
- 最後に、行データを JSON に置いて `tools/make_tsv.py` でシートに貼るタブ区切りを作る。出てきた ⚠️（日付のずれ・字数・1行の長さ・空欄）は直してから出す
- 「一気に」「まとめて」と言われたときだけ、段階1から段階2まで通しで出す

## 2. 組み方（共通）
1. **シートの今の行を先に見る**（貼ってもらう）。こちらの記録を前提に並びを出さない
2. **先方の意向を先に置く**：先方の依頼（キャンペーン・休業など）、売り出したい新商品
3. **先月の数字で決める**：配信先（全員か絞り込みか）、続けるネタ・やめるネタ
   - 同じ人に続けて送ると開封率が落ちる（インクアート：同じ約650人に5回で 42.6→30.1%）
   - 全員に送るとブロックが増える（インクアート9/29：3日で+25。絞り込みは+5〜9）
4. **月の型に当てはめる**（案件ファイルの「月の組み方」）
5. **季節**：その月に動くもの。前後検索・Googleトレンドのデータがあれば、それを根拠にする
6. **1通＝飛び先1つ**（リッチメッセージを分割して複数のURLにしない）

## 3. 書くときのルール（共通）
- **事実は飛び先のページ（LP）の本文にある物だけ。** 検索で拾った情報は、LP本文で確かめるまで書かない
- **先方に聞く前に、LP・新着・検索で取りにいく。** 載っていないと確かめてから聞く
- 先方サイト・LINE管理画面はこの環境から見られない（egressブロック。迂回しない）。本文は殿村さんに貼ってもらう（Claude in Chrome経由でよい）
- **殿村さんが意図して変えた文言は、戻す提案をしない。** 評価の軸は「取れるか」
- **直してと言われた物だけ直す。** 頼まれていない側を書き換えて代案にしない。先方の修正依頼の範囲を超えて変えない
- **テキストとバナーで、同じ物を同じ言葉で呼ぶ**（上の本文と下の画像は続けて読まれる）
- **絵文字は「何の話か」を1文字で伝えるもの**を選ぶ（飾りだけの絵文字は使わない）
- **LINEのテキストは1行12〜15字で折る**（プレビューの幅は全角14〜15字。超えると1〜2字だけ次の行に落ちる）。1吹き出し500字まで（改行も1字）。出すときは字数を添える
- **配信通数（上限・超過）は指摘しない**（殿村さんが管理画面で調整する）
- **配信時間はシートに書かない**（参考値として会話で渡す）
- 言葉：社内用語・比喩を使わない（「受け皿」ではなく「飛び先のページ」）。①②や略称を使うときは、同じメッセージの中で何を指すかを書く

## 4. 出す前のチェック
- [ ] テキスト→バナーの順で読み直し、呼び方まで揃っている
- [ ] 事実はLP本文にある物だけ
- [ ] 未確定の値が残っていない（あれば聞いた）
- [ ] 配信日と ga_campaign の日付が同じ（配信日が動いたら utm も直す）
- [ ] 1行の長さと字数（`make_tsv.py` の ⚠️ が出ていない）
- [ ] 案件ファイルの「書かないこと」に当たっていない
- [ ] バナー参考の画像生成プロンプトは全文（差分だけを出さない）
- [ ] 分からない列は空欄（推測で埋めない）

## 5. 出力と保存
- 会話：段階1＝表。段階2＝1本ずつ「【列名】値」＋最後にタブ区切りの行（コードブロック）
- **配信の予定を伝えるときは、`sheet_columns.md` の「配信予定の伝え方（12列）」の順で出す**（2026-10-07 殿村さん「今度からこのステータスにそって教えて欲しい」）
- ファイル：案件ファイルに書いた名前の `_drafts/…_YYYY-MM.md`。行データは同じ名前の `.json`
  - タブ区切り：`python3 .claude/skills/lineoa-monthly-plan/tools/make_tsv.py <json>`（ノーストは `--fmt norst`。シートの列の並びが違う）
  - 確認用：同じコマンドに `--view`
- 一区切りしたら commit & push し、`_memory/INDEX.md` と CLAUDE.md の記憶メモを更新する
- 例：`examples/inkart_20261005.json`（10/5 年賀状 超早割の行）

## 6. 月1回の自動下書き（まだ設定していない）
- 決まったら：毎月決めた日に新しいセッションで起動 → 段階1（枠）と「足りないもの」までを作ってファイルに置く → 殿村さんに知らせる
- 段階2（全文）は殿村さんのOKの後
- 作業ファイルがこの作業ブランチにしか無い場合は、先に本線（master）にまとめておく
