# マルチAIリレー・ワークフロー（Claude × ChatGPT/Codex）

**殿村さんはClaudeに言うだけ。** Claudeが依頼を書き、`codex` コマンドでChatGPT（Codex）を動かし、結果を読んで評価し、資料・SIMに落とす。
APIキーは使わない（デスクトップ版ChatGPTに同梱のコマンド版Codexが、ChatGPTのログインで動く）。

> **このスキルは2か所にある。更新するときは必ず両方を同じ内容にする。**
> ①`~/.claude/skills/multi-ai-relay/`（このPCのどのセッションからでも使える）
> ②`folder` リポジトリの `.claude/skills/multi-ai-relay/`（claude.ai/code・スマホ用）

## 1. 受け渡しの経路

| 場面 | 行き | 帰り |
|---|---|---|
| **PC（基本）** | Claudeが `requests/` に依頼を置き、**`codex` コマンドで実行** | Codexが `results/` に保存 → Claudeが直接読む。**殿村さんの手作業なし** |
| PC（予備） | コマンドが使えないとき、殿村さんがCodexアプリの ai-relay スレッドに「**次の依頼やって**」 | 同上。Codexが「保存しました」と返したら殿村さんが「保存した」と伝える |
| スマホ | 依頼をGitHubにpush → 殿村さんがChatGPTに「ai-relay の `requests/<ファイル名>` を読んで、書いてある通りに実行して」 | GitHubコネクタは読み取り専用 → 調査は**全文コピペ**／画像はDL |

- **同じ依頼をコマンドとアプリの両方で動かさない**（二重実行になる）
- Codexアプリで開くのは `ai-relay` フォルダだけ。**Downloads 直下や `folder` リポジトリを付けさせない**（GPTが読み書きできるようになる）
- スマホからRemote Control経由でPCのClaudeを動かす案は**一旦ステイ**（2026-10-24 殿村さん判断）

## 2. 基本フロー

```
① 案件受信（ざっくりでOK）
   ↓
② 調査の依頼を requests/ に置いて codex で実行
   ↓
③ results/ を読んで評価（主要な事実は公式ページで照合）
   ├─ 足りない／深掘りしたい → 追加の依頼を置いて②へ
   └─ 足りた → ④へ
④ スライド構成案を確定
   ↓
⑤ 構成が固まった時点で、画像が要る箇所を洗い出し → 画像の依頼をまとめて置いて codex で実行
   ↓
⑥ （随時）専門的見解が要る論点があれば依頼を置いて codex で実行
   ↓
⑦ 集まった情報を統合し、資料・SIMを作成
   ↓
⑧ 使い終わった依頼と結果を _archive/ に移す
```

- **各ステップの終わりに次にやることを一言で示す**（長い説明をしない）
- ⑤は都度作らない。**スライド構成が固まってから一括**（手戻り防止）。1依頼＝1枚
- 調査の結果は**要約させない**。全部 `results/` に残させて、取捨はClaudeがやる

## 3. 手順

- ローカル：`C:\Users\tonomura-r\Downloads\ai-relay`（Codex側のルールは同フォルダの `README.md`）
- リモート：`https://github.com/tonomura-r-dev/ai-relay`（private・スマホ用。`results/` と `_archive/` の中身は上がらない）

### Claudeがやること

1. `_templates/` から該当の雛形を読む（市場調査／画像生成／専門的見解）
2. 中身を埋める。**`<!-- Claude用メモ -->` のコメントブロックは消す**
3. `requests/YYYY-MM-DD_案件_用途.md` で保存し、`git add` → `commit` → `push`
4. **`codex` コマンドで裏実行する**（下記）。殿村さんには「動かしました。終わったら報告します」と1行だけ返す
5. 終わったら `git status` で `requests/`・README が無傷かを確認してから `results/` を読む
6. 評価して殿村さんに報告する。主要な数値・日付は公式ページで照合してから使う
7. **片付け**（下記）

### codex コマンド（2026-10-24 画像・調査とも動作確認済み）

- 本体：`$LOCALAPPDATA/OpenAI/Codex/bin/<ハッシュ>/codex.exe`。アプリ更新でハッシュが変わるので毎回探す
- 指示文は**UTF-8のファイルに書いて標準入力で渡す**（日本語を引数で渡すと文字化けの恐れ）。中身は：
  「README.md を読んでルールに従う／`requests/<ファイル名>` を1本だけ実行／書き込みは `results/` だけ／最後に保存したファイル名だけ返す」
  （ファイル名は明示する）。調査なら「Web検索で調べる。使えなければ理由を書いて終える」、画像なら「画像生成機能で作る。コードで描いて代用しない」も足す
- 実行（Bash・**必ず裏で実行**。画像1枚で約6分、短い調査で約2分）：
  ```
  C=$(ls -t "$LOCALAPPDATA"/OpenAI/Codex/bin/*/codex.exe | head -1)
  "$C" exec -C "C:/Users/tonomura-r/Downloads/ai-relay" -s workspace-write -c 'web_search="live"' --color never \
    -o "<scratchpad>/codex_last.txt" - < "<scratchpad>/codex_prompt.txt" > "<scratchpad>/codex_log.txt" 2>&1
  ```
- **`-s workspace-write` で書き込みを ai-relay の中だけに絞る。`--dangerously-bypass-approvals-and-sandbox` は絶対に使わない**
- 分かっている癖：
  - サンドボックス内でPowerShellが起動できない（アクセス拒否のエラー行が出る）。Codexは自前のJS実行で迂回して完了するので、結果を見て判断する
  - 起動時に `mcp.consensus.app` の認証エラーが1行出るが無関係
  - Web検索を使えたかはログの `web search:` 行で分かる
  - 画像は生成後にCodex自身が配色を直すことがある
  - 調査では「更新日」と「初回公開日」を見分けて期間外を外し、理由を注記してくれる。外された側に重要な更新が含まれることがある（テストでは「投稿」機能の全アカウント提供の延期）ので、注記も読む

### 片付け（必ずやる）

- 結果を読んで報告し終えたら、**その依頼と結果を `_archive/` に移す**（依頼は `git mv`、結果はそのまま移動）→ commit → push
- 画像を資料に使う場合は、移す前に「案件_用途.png」の日本語名で Downloads 直下にコピーする（即リネームのルール）
- `requests/` に済んだ依頼が溜まると、予備のアプリ経由で「次の依頼やって」としたときに古い依頼を拾う事故が起きる

### 置いてはいけないもの

- **クライアントの実名・売上・粗利・CPAの実数。** 依頼に必要な最小限だけ書く。実名が不要なら「A社（注文住宅・関東）」のように伏せる
  （ChatGPTは個人契約のアカウントだが、この伏せ方で問題なしと殿村さん判断＝2026-10-24）
- 認証情報（`*.json` / `.env` / APIキー）
- 社内資料そのもの（`.pptx` / `.xlsx` / `.pdf`）

> ⚠️ **`tonomura-r-dev/folder` には絶対にコネクタを繋がない。** 古河林業のCPA、ニナファームの単価、各社の売上が全部入っている。

## 4. 雛形

| 雛形 | 用途 | 肝 |
|---|---|---|
| `_templates/市場調査.md` | 市場・競合データ、一次情報・論文の収集 | 全数値に出典併記／推測は`【推測】`／**要約させない** |
| `_templates/画像生成.md` | スライド用の図解・イメージ | **1ファイル＝1枚**／画像内に文字を入れない／配色と禁止事項を毎回書く |
| `_templates/専門的見解.md` | 論点の壁打ち | メリット・デメリット・代替案の3点だけ／立場を取らせる |

### 雛形を埋めるときの注意

**市場調査**
- 「市場規模」ではなく「◯◯業界の国内市場規模の直近3年推移」まで具体で書く
- 出典の範囲を指定する（LINE関連なら lycbiz.com／linebiz.com／LINEヤフーのプレスリリースに限る、など）
- 戻ってきた**検索広告のCPC/CPAは、LINE提案の獲得単価の根拠には使わない**（Claude側で弾く）
- Googleトレンド・前後検索のKWはGPTに投げない（1語ルールがあるのでClaude側で扱う）

**画像生成**
- **A案/B案の複数出しは禁止。** 迷うときは先に方向性を文章で確認してから確定版1本だけ出す
- 色だけでなく**トンマナ（線・角丸・余白・赤の使い所）も毎回書く**
- 系列色は `3467B2`／`D9661F`／`00897B`／`8E4EC6`。`1F285A`・`333333` は暗すぎて使わない
- 禁止は明示しないと足される（十字マーク、ロゴらしき図形）。指定しない部分（例：手の肌色）はCodexが自分で決める
- 人物の表情は「微笑まず」ではなく「穏やかに受け止めている表情」と**どうあってほしいか**を書く

## 5. 情報統合フェーズ（⑦）

1. 出典ラベルを分ける（lineoa-industryスキルの鉄則と同じ：業界指標／自社実績／仮置き★／GPT調査／GPT見解、を混ぜない）
2. lineoa-industryスキルのセクション10（個別案件5ステップ）に接続する場合は、③データ依頼の実質的な中身がこのフローの②〜③、⑤⑥に相当する
3. 資料はpptxスキル、SIMは lineoa-sim／lineoa-sim-edit スキルで作成

## 6. セッションを跨いだ引き継ぎ

- **同じ端末間で会話を続けたいだけ** → 同じセッションURL（claude.ai/code）を別端末で開けば会話はそのまま続く
- **別々に始めた案件同士でも文脈を共有したい**→ 自動共有はできない。案件が一区切りついたら必ず次の2つをやる：
  1. `_drafts/<案件名>_要件定義（引き継ぎ用）.md` に、前提・進捗・GPTから得た情報の要点・未完タスクをまとめる
  2. `CLAUDE.md` の「記憶メモ」に1〜3行で追記し、上記ファイルへのリンクを貼る
- `ai-relay/_archive/` に済んだ依頼と結果が残るので、何をGPTに聞いたかの記録になる（ローカルのみ）
