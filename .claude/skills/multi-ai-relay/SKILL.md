# マルチAIリレー・ワークフロー

**前提：Gemini・ChatGPTとのAPI連携はしない。** 殿村さんが各アプリを手動で行き来する「人力リレー」。
Claudeの仕事は ①次に投げるプロンプトを完成形で作る ②戻ってきた出力を評価する ③最終的に資料・SIMに落とす、の3つ。

> **2026-10-24 変更：ChatGPT宛はフォルダ `ai-relay` で受け渡す。**
> PCではデスクトップ版ChatGPT（2026年7月にCodexと統合・ローカルフォルダを読み書きできる）が
> 結果を `results/` に保存するので、**行きも帰りもコピペ不要**。殿村さんの手作業は「次の依頼やって」の1行だけ。
> スマホ時だけGitHub経由（帰りはコピペ）。Geminiは従来どおりコピペ。

## 0. 役割分担（固定）

| 役割 | 担当 | 用途 |
|---|---|---|
| 検索・分析・要約 | **Gemini** | 市場データ、競合データ、数値の裏取り、前後検索傾向など |
| 画像生成 | **ChatGPT** | スライドに入れる図解・イメージ画像 |
| 進め方の洗い出し／専門的見解 | **ChatGPT** | 進行方針のたたき台、専門的な視点からの意見出し |
| 情報収集（サイト・学術論文・研究の引用） | **ChatGPT** | 出典つきの一次情報収集 |
| 統合・実行 | **Claude（自分）** | 上記の出力をまとめて資料・SIMに実装 |

## 1. 受け渡しの経路

| 相手 | 行き（指示を渡す） | 帰り（結果を受け取る） |
|---|---|---|
| **ChatGPT（PC）＝基本** | `ai-relay/requests/` に依頼ファイルを置く | GPTが `ai-relay/results/` に保存 → **Claudeが直接読む** |
| ChatGPT（スマホ） | 上に加えてGitHubにpush | GitHubコネクタは読み取り専用 → 調査は**全文コピペ**／画像はDL |
| **Gemini** | コピペ（そのまま送れる完成形で出す） | 全文コピペ |

- PC側はデスクトップ版ChatGPTの**プロジェクト「ai-relay」（ソースフォルダー＝`C:\Users\tonomura-r\Downloads\ai-relay`）の中の決まった1チャット**だけを使う。チャットを増やさない
- 殿村さんの手作業は、そのチャットに「**次の依頼やって**」と送る1行だけ。これもゼロにするにはAPI連携が要るので、やらない
- ソースフォルダーに **Downloads 直下や `folder` リポジトリを付けさせない**（GPTが読み書きできるようになる）

## 2. 基本フロー

殿村さんが外出先などで案件情報をざっくり投げてきたら、この順で進める。
**各ステップの終わりに次にやることを一言で示す**（スマホで読む前提。長い説明をしない）。

```
① 案件受信（ざっくりでOK）
   ↓
② Claude → Gemini調査プロンプトを生成
   ↓（殿村さんがコピペしてGeminiに投げる）
③ Gemini出力を全文コピペで受け取る → Claudeが評価
   ├─ 情報が足りない/深掘りしたい → 追加プロンプトを再生成 →②に戻る
   └─ 足りた → ④へ
④ スライド構成案を確定
   ↓
⑤ 構成が固まった時点で、画像が要る箇所を洗い出し→ ai-relay/requests/ に画像依頼を置く
   ↓（殿村さんがChatGPTに「次の依頼やって」→ results/ に画像が入る）
⑥ （随時）専門的見解・情報収集が要る論点があれば ai-relay/requests/ に依頼を置く
   ↓（殿村さんがChatGPTに「次の依頼やって」→ results/ に結果が入る）
⑦ 集まった情報を統合し、資料・SIMを作成
```

- ②〜③は複数ラウンド往復してよい。**Gemini出力は要約せず全文コピペしてもらう**（Claude側で必要な部分を判断する）
- ⑤は都度作らない。**スライド構成が固まってから一括**で画像プロンプトを出す（手戻り防止）
- ⑥は①〜⑦のどのタイミングでも発生しうる

## 3. ai-relayの手順（ChatGPT向け）

- ローカル：`C:\Users\tonomura-r\Downloads\ai-relay`（GPTのルールは同フォルダの `README.md` に書いてある）
- リモート：`https://github.com/tonomura-r-dev/ai-relay`（private・スマホ用）

### Claudeがやること

1. `_templates/` から該当の雛形を読む（市場調査／画像生成／専門的見解）
2. 中身を埋める。**`<!-- Claude用メモ -->` のコメントブロックは消す**
3. `requests/YYYY-MM-DD_案件_用途.md` で保存
4. `git add` → `commit` → `push`（スマホ経由でも読めるように。`results/` はGitHubに上がらない設定）
5. 殿村さんには「**ChatGPTに『次の依頼やって』と送ってください**」と1行だけ返す（プロンプト本文を会話に貼らない）

### 殿村さんがChatGPTに送る文

- PC：プロジェクト「ai-relay」の決まったチャットに **「次の依頼やって」**
  （GPTは `results/` に結果が無い依頼のうち一番古いものを実行する、とREADMEに書いてある）
- スマホ：「ai-relay の `requests/<ファイル名>` を読んで、書いてある通りに実行して」→ 回答を全文コピペで戻してもらう

### 結果を受け取る

- `results/<依頼と同じ名前>.md`（調査・見解）／`.png`（画像）を読む
- 画像を資料に使うときは「案件_用途.png」の日本語名で Downloads 直下にコピーする（即リネームのルール）

### 済んだ依頼

依頼と結果を `_archive/` に移す。requests を溜めるとGPTが別の依頼を拾う事故が起きる。

### このリポジトリに置いてはいけないもの

- **クライアントの実名・売上・粗利・CPAの実数。** 依頼に必要な最小限だけ書く。
  実名が不要なら「A社（注文住宅・関東）」のように伏せる
- 認証情報（`*.json` / `.env` / APIキー）
- 社内資料そのもの（`.pptx` / `.xlsx` / `.pdf`）

> ⚠️ **`tonomura-r-dev/folder` には絶対にコネクタを繋がない。**
> 古河林業のCPA、ニナファームの単価、各社の売上が全部入っている。
> ChatGPTに渡すのは `ai-relay` だけ。

## 4. 雛形

| 雛形 | 用途 | 肝 |
|---|---|---|
| `_templates/市場調査.md` | 市場・競合データ、一次情報・論文の収集 | 全数値に出典併記／推測は`【推測】`／**要約させない** |
| `_templates/画像生成.md` | スライド用の図解・イメージ | **1ファイル＝1枚**／画像内に文字を入れない／配色と禁止事項を毎回書く |
| `_templates/専門的見解.md` | 論点の壁打ち | メリット・デメリット・代替案の3点だけ／立場を取らせる |

### 雛形を埋めるときの注意

**市場調査**
- 「市場規模」ではなく「◯◯業界の国内市場規模の直近3年推移」まで具体で書く
- 戻ってきた**検索広告のCPC/CPAは、LINE提案の獲得単価の根拠には使わない**（Claude側で弾く）
- Googleトレンド・前後検索のKWはGPTに投げない（1語ルールがあるのでClaude側で扱う）

**画像生成**
- **A案/B案の複数出しは禁止。** 迷うときは先に方向性を文章で確認してから確定版1本だけ出す
- 色だけでなく**トンマナ（線・角丸・余白・赤の使い所）も毎回書く**
- 系列色は `3467B2`／`D9661F`／`00897B`／`8E4EC6`。`1F285A`・`333333` は暗すぎて使わない
- 禁止は明示しないと足される（十字マーク、ロゴらしき図形）
- 人物の表情は「微笑まず」ではなく「穏やかに受け止めている表情」と**どうあってほしいか**を書く
- 受け取ったら即リネーム：「案件_用途.png」の日本語名で Downloads 直下へ

## 5. Geminiプロンプトの作り方（②）

**そのままコピペして送れる完成形**で出す。殿村さんが背景情報を書き足す必要がないようにする。

必須要素：
1. 背景（クライアント名・業界・現状の課題・提案の目的）— 殿村さんから聞いた情報をそのまま埋め込む
2. 調べてほしい項目を箇条書きで具体的に
3. 出力フォーマット指定（表形式／箇条書き／数値には出典を必ず併記、など）
4. 「出典のない推測は明示的に『推測』とラベルする」よう指示に含める

出力の最後に「このプロンプトをそのままGeminiに貼ってください」と一言添える。

### 再プロンプト（③で不足時）
Geminiの出力を読んで、何が足りないかを判定してから再生成する。パターン：
- 数値の出典が薄い → 「◯◯の数値の一次情報・出典を追加で示して」
- 深掘りしたい論点が出た → その論点だけを狭く聞き直す
- 殿村さん自身が「ここ詰めて」と言った場合はその指示をそのままプロンプトに組み込む

## 6. 情報統合フェーズ（⑦）

Gemini・ChatGPTから集まった出力（全文コピペされたテキスト、画像ファイル）を踏まえて：

1. 出典ラベルを分ける（lineoa-industryスキルの鉄則と同じ：業界指標／自社実績／仮置き★／Gemini調査／ChatGPT見解、を混ぜない）
2. lineoa-industryスキルのセクション10（個別案件5ステップ）に接続する場合は、③データ依頼の実質的な中身がこのフローの②〜③、⑤⑥に相当する
3. 資料はpptxスキル、SIMは lineoa-sim／lineoa-sim-edit スキルで作成

## 7. セッションを跨いだ引き継ぎ

- **同じ端末間で会話を続けたいだけ**（スマホで始めてPCで続き）→ 同じセッションURL（claude.ai/code）を別端末で開けば会話はそのまま続く。特別な作業は不要
- **別々に始めた案件同士でも文脈を共有したい**→ 自動共有はできない。案件が一区切りついたら（または長くなったら）必ず次の2つをやる：
  1. `_drafts/<案件名>_要件定義（引き継ぎ用）.md` に、前提・進捗・Gemini/ChatGPTから得た情報の要点・未完タスクをまとめる
  2. `CLAUDE.md` の「記憶メモ」に1〜3行で追記し、上記ファイルへのリンクを貼る（次のセッションが最初に読む場所はここ）
- この2点をやらないと、次のセッションはこのやり取りを一切覚えていない
- **`ai-relay` の `requests/` に残っている依頼ファイル自体も引き継ぎ材料になる**（何を誰に聞いたかの記録）
