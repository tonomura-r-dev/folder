# 既存案件の一覧を作る

月次管理ブック（部署集計）から、既存顧客の案件一覧を作る。
営業が「既存のお客さんに別商材を提案する」ために使うリストなので、
**エンドクライアント名と担当者が1行ずつ並んでいること**が価値の中心にある。
集計表やサマリではない。

作り始める前に、リポジトリの `CLAUDE.md` の「記憶メモ」を読むこと。
シートのIDや、その時点で決まっている除外条件はそちらに書いてある。
このスキルには社内の固有名詞と実額は書かない（使い回すものなので）。

## 進め方（この順番を外すと必ず手戻りする）

### 1. 依頼の言葉ではなく、目的を先に確かめる

「商材カテゴリ×契約形態×売上×粗利×担当が分かるように」のような**切り口の言葉**を
渡されることがある。そのまま集計表を作ると外す。実際に欲しかったのは
**既存アタックに使う明細**で、集計表では「担当が分からない」「エンド名が無い」と
差し戻された。

**この数字を誰が何に使うのか**を先に一言確認する。ここで1往復すると、
あとの3往復が消える。

### 2. 列名を言われたら、その並びのまま1行=1レコードで出す

依頼者が列名を並べて指定してきたら、それは**明細の仕様**であって
集計の指示ではない。指定された並びのまま、1行=1件で出す。

**集計・サマリ・数式・スクリプトは、頼まれるまで作らない。**
「関数とかいらないんだよね」と言われる。全部を値で書く。

### 3. まずファイルで渡す

xlsx と TSV を渡して、貼るかどうかは相手に決めてもらう。
貼る場所と貼り方が決まってから、必要ならスクリプトを作る。
この順番の理由は下の「共有シートに勝手に書き込まない」に書いた。

## 出力の形

**1行 = 1案件。指定された列の並びのまま。** 例として、直近で承認された形は11列。

```
商材 / クライアント名 / エンドクライアント名 / 商材詳細 /
ストック売上 / ストック利益 / 売上 / 利益 / 担当者1 / 担当者2 / 担当者3
```

- 数式は1つも入れない。全部が値
- サマリシート・集計シートは作らない。明細だけの1シート
- ストック売上・ストック利益は、**計上種別が「ストック」の案件だけ**入れる。
  ショットの行は空欄。売上・利益は契約形態に関係なく全件入れる
- 担当者1〜3 は `アカウント` `コンサル` `運用①②③` の順に、重複を除いて3人まで

## 実行

```bash
python _build/build_annken_list.py <月次管理ブック.xlsx> <出力先ベース名> --OA除外
```

| 出力 | 用途 |
|---|---|
| `<ベース名>.xlsx` | 中身の確認用。ここからコピーして貼るのが一番早い |
| `<ベース名>.tsv` | 見出し無し。既にある表の途中に貼るとき |
| `<ベース名>_見出し付き.tsv` | 1行目が見出し。新しいタブを作って貼るとき |

- `--OA除外` … LINE公式アカウントの媒体を外す。提案先がLINE OAなら普通は外す
- `--アカウント貸し込み` … 既定では外している。全部入れたいときだけ付ける

抽出そのものは `_build/build_attack_list.py` の `extract()` に集約してある。
別の切り口が要るときも、この関数を共有して使う。

## 元ブックの読み方（ここで何度も踏んだ）

依頼者が言う「部署集計の各商材」は、月次管理ブックの**媒体タブ**のこと
（AD / アフィ / CS / MEO / 制作 / PR / 風評 / タレントシェア /
LINE公式アカウント / メディア / ベトナム / ASP / マス広告(MA)・その他）。

- **列は位置ではなく見出し名で引く。** 媒体ごとに並びが違う。
  ASPだけ担当の列名が `広告主担当①②` `媒体担当①②` になっている
- **契約形態は `計上種別` の値そのもので判定する。** 金額で判定すると、
  金額0のヨミ案件が「未設定」に落ちる
- **件数の数え方は1箇所に統一する。** 請求額の有無で数える場所と
  計上種別で数える場所が混ざると、差分がマイナスになる
- **`発注先名` は一部の媒体にしか無い。** ADには無い
- **業界の列は存在しない。** 社名から推定するしかない（`_build/gyokai.py`）
- 担当は按分列（アカウント／コンサル／運用①②③）に分かれている。
  按分前の金額を担当ごとに足すと三重計上になる

## TSVを書くときの注意

セルの中にタブや改行が入っていることがある。実例では商材詳細に
タブが混ざっていて、その行だけ列数が増えて貼り付け位置がずれた。
**タブ・改行は潰してから書く。** 書き出したら列数を必ず確認する。

```bash
awk -F'\t' '{print NF}' <出力>.tsv | sort -u   # 想定の列数だけなら正常
```

## ★共有スプレッドシートには勝手に書き込まない

一番大事なところ。実際に**本番の共有シートに足した列が消され、タブごと
版履歴から戻す**ことになった。原因は、頼まれていない「行を足すスクリプト」
「列を足すスクリプト」を先に作って渡し、実行できる状態にしてしまったこと。
「これは要りますか」を一度も聞いていなかった。

**順番はこう。**

1. まず**ファイルで渡す。** 貼るかどうかは相手が決める
2. 貼る場所と貼り方を相手が決めてから、必要ならスクリプトを作る
3. 共有シートへの書き込みは、**依頼された時だけ**

「元のシートを触らないで」と言われたら、**列を足すのも触ることに入る**と考える。
安全なのは別ファイルで渡すことだけ。

どうしても書き込む場合は、

- 新しいタブを作るか、**表の右端に列を足す**方向で考える。
  行の挿入・削除・並べ替えはしない
- 先に**書き込まないプレビュー**を用意して、何行ヒットするかを見せる
- **取り消す手段**を必ず付ける（入れた範囲を控えて、それだけ消す）
- **本番の前にコピーで試す。** ただしコピーは本番から作り直すこと。
  前の検証で中身が置き換わったコピーで試しても意味がない

参考実装: `_build/add_5cols_gs.gs`（右端に列を足す・取り消し付き）。

## Google スプレッドシートには直接アクセスできない

`docs.google.com` はこの環境からブロックされている。読むことも書くことも
できない。シートを触る必要があるときは **GAS を書いて相手に貼ってもらう**形になる。

- 本番とコピーは**別のスクリプトプロジェクト**。コピーで通した認証は本番では効かない。
  メニューを押してエラーが出て、実行ログに `onOpen` しか残っていなければ
  **認証が未了**。エディタから書き込まない関数を1回実行して認証を通す
- 月次管理ブックは大きい。80列全部読むと6分制限に引っかかる。
  見出し行だけ先に読んで、**使う列の右端までしか読まない**

## 数字を見せる前に言っておくこと

- **除外条件を変えると、売上上位の会社が丸ごと消えることがある。**
  黙って出すと「1位が違う」と言われる。除外の影響（件数・金額・消える会社数）を
  先に出す
- **同じ会社が複数行に出る。** 会社単位で集計した数字を行ごとに貼ると、
  単純合計で多重計上になる。合計を出す用途があるか先に確認する
- **社名とエンド名が違う案件が3割ある**（代理店経由）。エンドに直接電話すると
  代理店の頭越しになる。リストを渡すときに一言添える

## 社内数字をリポジトリに残さない

生成物と元ブックは `.gitignore` に入れる。スクリプトは数式とロジックだけなので
コミットしてよい。

**★英数字名のコピーがすり抜ける。** 日本語名だと落とせない環境向けに
英数字名のコピーを作ることがあるが、`.gitignore` が日本語名しか見ていないと
そのコピーだけコミットされる。実際に一度やった。
**コピーを作ったら、その場で `.gitignore` にも追記する。**

コミット前に確認する。

```bash
git ls-files | grep -iE '\.(xlsx|tsv|csv)$'
```

出てきたファイルに実額が入っていないか中身を見る。数式だけなら残してよい。
