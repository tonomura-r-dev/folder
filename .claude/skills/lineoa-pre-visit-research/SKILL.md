# LINE OA 初訪前調査ビルダー

営業が初回訪問の前に「このLPならこう攻める」という提案仮説を持ち込むための、調査兼提案ドキュメントを作るスキル。成果物は **第1部：想定ユーザー動線（8フェーズ）** と **第2部：LINE公式アカウント運用プラン** の2部構成のMarkdown。

姉妹スキル `dym-line-proposal` はSIM読解・バナー制作・PPTX資料化まで含むフル提案ビルダー。このスキルは**その手前の「頭出し」＝Markdownの調査・提案ドキュメント**に絞る。資料化まで求められたら dym-line-proposal に切り替える。

## 基本スタンス（全工程で守る）

このスキルの価値は「AIが出しがちな一般論」ではなく、**現場ですぐ使える具体・仮説・逆張り**にある。以下を徹底する。

- 書く順序は **仮説構築 → 戦略設計 → 実装指針**。プロ運用者の思考プロセスとして、なぜそう考えるかを添えて論理を追えるようにする。
- 抽象論を禁じる。配信文面なら見出し例、施策なら誰にいつ何を出すか、まで具体で落とす。「エンゲージメントを高める」で止めない。
- **AI的な安全回答をしない。** 勝ち筋があるならリスクのある逆張り・尖った仮説も提示する。ただし断定はしない（下記）。
- **人間の判断が要る箇所・推測・要確認は明示する。** LPから読み取れない事実（実際の客単価、解約率、計測可否、ツール仕様など）を勝手に断定しない。「※要確認」「※仮説」と注記し、初訪でヒアリングすべき論点として立てる。
- 景表法に触れうる比較・断定表現（「必ず」「最安」等）は避け、モデルケースとして注記する。
- 情報源の列挙は不要。ただしLPの実データ（料金・プラン・申込フロー）は必ず一次情報で押さえる。

## 対話フロー（各ステップで止まる）

このドキュメントは工程順に積み上げる。**ユーザーが「まとめて全部出して」と言わない限り、各パートを出したら止まり、次の指示・入力を待つ。** 先回りして全部書き切らない。理由は、初訪前調査は営業担当のドメイン知識で途中修正が入る前提だから。途中のパートから入る（例：動線はいいからLINE企画だけ）のも可。

**まず進め方を1行で決める（重要）：**
- **既定は対話型。** URL＋KWがあっても、各パート（前提分析→第1部→第2部）を出すたびに止まり、次の指示を待つ。初訪前調査は営業のドメイン知識で途中修正が入る前提だから。
- **一括型に切り替えるのは、ユーザーが「一気に」「まとめて」「通しで」等と明言したときだけ。** その場合は前提分析→第1部→第2部を止めずに通しで書き、最後に確認する。
- 判断に迷う指示（例：「作って」だけ）は既定＝対話型で進め、前提分析を出した所で一度止まる。

標準フロー（対話型）：

1. **入力受領** — ユーザーから `参考URL` / `メインKW` /（任意）`想定ターゲット` を受け取る。足りなければ求めて待つ。特に参考URLとメインKWは必須。
2. **前提分析（内部）** — LPを読み込み、サービス・ターゲット・ベネフィット・検索意図を掴む（次節）。ここは短く要約提示し、認識ズレがないか確認して**止まる**。
3. **第1部：想定ユーザー動線** を出力して**止まる**。
4. **第2部：LINE運用プラン** を出力して**止まる**。
5. 修正指示（FP）を反映。必要なら通し版Markdownを1ファイルにまとめる。

## 前提分析（第1部を書く前に必ずやる）

ここがズレると以降すべてズレるので、LPは実データで押さえる。

1. 参考URLを `WebFetch` で読む。**料金・プラン・決済方法・申込フロー・利用シーン**を必ず具体で把握する（料金ページ、申込URLのパラメータまで見る）。大手サイトはトップが薄く、料金/エリア/申込の詳細ページが別URL（/price, /menu, /area 等）にあることが多い。トップだけで足りなければ、料金ページや `WebSearch`（"サービス名 料金" 等）で一次情報を補ってから進む。それでも取れない事実は勝手に埋めず「※要確認（初訪でヒアリング）」として論点化する。読めない/ブロックされたら、その旨を伝え、分かる範囲で進めるか情報提供を求める。
2. **メインKWの検索意図**を言語化する。顕在（今すぐ客）か潜在（情報収集）か、その検索をする人の心理状態は何か。ここに動線設計を合わせる。
3. **ターゲットは多くの場合、性質の異なる2ペルソナに割れる**（例：本人 vs 家族、初回 vs リピート、価格重視 vs 品質重視）。決め打ちせず割れ方を提示する。想定ターゲットが指定されていればそれを軸に、無ければ仮説で2つ立てる。
4. **この事業の"本当の経済構造"**を一段深く読む。単発ECか継続獲得か、客単価とLTVの差、解約・早期離脱のペナルティ、粗利の出どころ。LINEで引き上げるべきKPIがここで決まる。
5. 掴んだ内容を4〜6行で要約し、「この理解で合っていますか」と確認して次へ。

## 第1部：想定ユーザー動線（カスタマージャーニー）

ターゲットがサービスを知りリピートするまでを、以下の**8フェーズ**に分けて書く。各フェーズで必ず「**ユーザーの行動・心理**」と「**企業側の具体施策**」の2軸を、上記の分析に紐づけて具体化する。特に④〜⑥はこのスキルの肝（LINEが効く領域）なので厚く書く。

1. **① 接触（認知・流入）** — どのKW/媒体/文脈で出会うか。検索意図と流入面を対応づける。
2. **② 離脱（サイト離脱と引き戻し施策）** — どこで・なぜ離脱するか。EFO、リタゲ、LINE前段の引き戻し。
3. **③ 育成・教育（リード獲得前の興味喚起）** — 登録前に信頼と必要性をどう作るか。
4. **④ リード獲得（WEBフォーム誘導 vs LINE登録誘導の分岐点）** — ここが最重要の分岐。どちらに寄せるか、なぜか、両立させるならオファー設計をどうするかを明記する。
5. **⑤ リード有効化（登録後の本気度スクリーニング）** — 冷やかしと見込み客をどう分けるか。
6. **⑥ 有効リードの育成（ナーチャリング）** — セグメント別に何を届けて温度を上げるか。
7. **⑦ マネタイズ（商談・成約・購入）** — 引き上げのトリガーとオファー。
8. **⑧ リピート（リピート購入・複数展開・紹介）** — LTV最大化と紹介動線。

書き方は、各フェーズを見出しにして「行動・心理」→「施策」の順。表形式が見やすければ表でよいが、施策は必ず具体（誰に/いつ/何を/どの機能で）。

## 第2部：LINE公式アカウント運用プラン（具体策）

第1部の動線（特に④〜⑥）を最大化するLINEコンテンツを、以下の5項目で出す。**すべてメインKW・サービス内容・第1部の仮説に紐づける**。汎用テンプレの貼り付けは禁止。

### 1. ステップ配信（シナリオ構成案）
友だち追加直後から、教育→オファー（⑦への誘導）までを **5〜7通** で設計。各通に「**配信日（例：0日/翌日/3日後…）**」「**目的**」「**メッセージの概要・見出し**」を書く。1通ごとに何を信じてもらい次の行動を取らせるかを明確にする。

### 2. 季節・時期ごとの企画配信
メインKWとサービスに紐づけた、春夏秋冬（または業界特有の繁忙期/閑散期）のキャンペーン/イベント配信アイデアを **4つ**。各案に狙い・訴求・想定オファーを添える。業界の商習慣・需要の山谷を踏まえる。

### 3. アンケート（サービスに直関与）
ニーズ把握・リソース確認・直接的セールスオファー（⑤リード有効化）につなげる設問を **3〜5つ**。各設問の意図（何を判定し、回答でどう分岐/追客するか）を併記する。

### 4. アンケート（直接は非関与・診断で長期追客する動線）
商品アピールではなく、ユーザーの「現在の状態・悩み」を診断する**ゲーム感覚のアンケート**。診断結果を **3〜4パターン**に分類し、各パターンの特徴と、**結果別セグメント配信の方向性**（長期的な⑥への追客シナリオ）を示す。ここは離脱しにくく友だちを資産化する設計思想を効かせる。

### 5. 想定される離脱・ハードルと対策
LINE運用で起きる離脱ポイントを **3つ**挙げる（例：そもそも登録しない／動画を見ない／行動しない）。それぞれに、**LINEの機能（リッチメニュー、カルーセル、ステップ配信、リッチメッセージ等）とコピーライティング**を使った具体的な解決策を対応づける。

## 出力形式

- Markdownで、`# 第1部` / `# 第2部` と見出しを付けて見やすく。
- 冒頭に3〜5行のエグゼクティブサマリ（このLPをどう攻めるかの結論仮説）を置くと初訪で刺さる。
- 各所で「※仮説」「※要確認（初訪でヒアリング）」を明示し、断定と推測を混ぜない。
- 長くなるので、通し版は1つの `.md` ファイルにまとめて `SendUserFile` で渡す（ユーザーがそのまま持ち出せる形にする）。
- 会話上の返信は簡潔に。ドキュメント本文はファイル側に置き、チャットには要点と確認事項だけ書く。
