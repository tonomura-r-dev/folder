# 実例：架空の美容サロンのスクショからシナリオ案を作る（Phase 6 の検証）

- 対象：`mock-oa.html` で作った**架空**の美容サロンの既存アカウント（店名・電話・URLも架空）
- スクショ：`screenshots/01〜05`（実際のワークフローでは `projects/sample-beauty/screenshots/` に置く。そちらはリポジトリに入らない）
- 作った提案：`projects/sample-beauty/patches/20261027-0130_salon_from_screens.json`（このフォルダにも写しを置いた）
- 手順：スキル `line-sim-screens`（`docs/AI_WORKFLOW.md`）どおり。`npm run patch:check` は1回目でOK

## 見えたもの（確認済み）

| スクショ | 写っていたもの |
|---|---|
| 01 | 友だち追加直後のトーク。挨拶「友だち追加ありがとうございます！／〔店名〕です。／はじめての方には、カット20%OFFのクーポンをお送りしています。／まずは2つの質問にお答えください。」。1問目「ご希望のメニューは？」［カット／カラー／パーマ］。リッチメニュー3列×2行［ご予約／メニュー・料金／クーポン／スタイル写真／アクセス／お問い合わせ］。アカウント名に店名・支店名 |
| 02 | 1問目に「カラー」と答えたあと、2問目「当店のご利用は？」［はじめて／2回目以上］ |
| 03 | 「クーポン」と送ると、カード「はじめての方限定クーポン／カット20%OFF（初回のみ）／ご予約のときに「LINEを見た」とお伝えください。」［このクーポンで予約する］ |
| 04 | 「ご来店から1か月」の配信「前回のご来店から1か月が経ちました。／そろそろカラーのリタッチはいかがですか？」と、カード「今週の空き状況／平日の午前は比較的空いています。」［空き状況を見る］ |
| 05 | Webの「ご予約フォーム」（お名前・電話番号・ご希望のメニュー。4つ目の項目はポップアップで隠れて読めない）。離脱しようとしたときのポップアップ「予約の前に、LINEでクーポンを受け取りませんか？／はじめての方はカット20%OFF。空き状況のお知らせも届きます。」［LINEで受け取る］［閉じる］。URLに店名 |

**伏せたもの**：店名・支店名（〔店名〕）、URLの店名部分。会社名は「ヘアサロンサンプル（仮）」。

## 推定したもの（AI推定・承認待ち）

| 推定 | 根拠 |
|---|---|
| アンケートの回答ごとにタグを付ける（希望メニュー3種・来店回数2種） | 挨拶とクーポンが「はじめての方」向け、04が「カラーのリタッチ」なので、回答で出し分けていると考えた |
| 来店回数で分岐：2回目以上 → 来店1か月後の配信／はじめて・未回答 → 初来店向けの配信 | 同上 |
| 初来店向け：翌日12:00にクーポンをもう一度、3日目19:00にスタイル写真の案内。予約したら止める | スクショには無い。メニューの「スタイル写真」と、予約が目的であることから提案 |
| 来店1か月後の配信は Day 28 10:00（アンケートに答えた日から4週間後） | LINEでは来店日が分からないため。1週間以内に予約した人には送らない |
| 予約（CV）：フォーム送信で記録 → お礼 → 4週間後に04の配信 | 予約フォームがあり、メニュー先頭が「ご予約」 |
| 「クーポン」の自動応答を、2回目以上の人には別の文面にする（文面は【要確認】の枠だけ） | 03の返信は「はじめての方限定」で、常連に返すのは不自然 |
| リッチメニューの各区画を押したときの動き | 区画の文字は写っているが、押した結果は写っていない |
| 予約フォームの4つ目の項目「ご希望の日時」・「ご希望のメニュー」の選択肢 | ポップアップで隠れていた |
| 予約完了ページとLINE誘導、経路（ポップアップ／完了ページ） | スクショには無い |
| デモ用のペルソナ3人と台本・説明文3件 | デモで流すため |

## 特に確かめてほしい点

1. **来店1か月後の配信の起点**：本来は来店日の30日後。シミュレーターでは「アンケートに答えた日／予約した日から4週間後」にしている。
2. **2回目以上の人への「クーポン」の返信**：文面は仮（【要確認】）。店舗に確認して差し替える。
3. **リッチメニューの各区画の動き**（特に「メニュー・料金」「スタイル写真」が、ページを開くのか返信なのか）。

## この実例で見つかったこと

- 自動応答（「クーポン」）が、1時間前に配信した同じクーポンと「重複」とみなされて返らない不具合が見つかった。
  頼まれた返事が届かないのは不自然なので、**自動応答は重複防止の対象外**にした（エンジンの汎用的な修正。業種固有の変更ではない。人材の検証案件の結果は変わらない）。
