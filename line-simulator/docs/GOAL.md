# GOAL — LINE施策統合シミュレーター

最終更新：2026-10-26（Phase 1）

---

## 1. このツールが解く問題

LINE公式アカウントの提案は、**実装前に「動くもの」を見せられない**。
そのため商談では、

- リッチメニューを押したら何が起きるのか
- アンケートに答えると、裏でどのタグが付くのか
- 東京希望の人と大阪希望の人に、別の配信が飛ぶとはどういうことか
- 応募した人には、もう追わない（＝停止する）とはどこで判定しているのか

を、口頭とスライドで説明するしかない。
聞き手は「なんとなく分かった」で終わり、**構築後に「思っていたのと違う」が出る**。

このツールは、その説明を**操作して見せられる状態**にする。

---

## 2. Goal（完成状態の定義）

> 営業担当者が、案件ごとのLINE施策を**実装前に**組み立て、
> 顧客の前で**実際に操作しながら**「ユーザーに何が見えるか」と「裏で何が起きているか」を
> 同時に説明できる。
> そのデモは、1個のHTMLファイルとして顧客に渡せる。

これを満たすために3つを作る。

| # | 成果物 | 誰が使うか | 置き場所 |
|---|---|---|---|
| ① | ローカル編集ツール | 社内（提案を作る人） | 社内PCのみ |
| ② | 統合シミュレーター | ①の中で動く（②は①の一機能） | 社内PCのみ |
| ③ | 営業用HTML | 顧客・社外 | 単一ファイルで配布 |

③は①から書き出す。**①と③は同じシナリオデータ・同じ判定ロジックで動く**（別実装にしない）。

## 3. 完成条件（これが全部できたら完成）

### 3.1 操作して見せられる

- [ ] リッチメニューを押すと、トーク画面にメッセージが出る／Webページに飛ぶ
- [ ] キーワードを送ると、設定どおりの自動応答が返る
- [ ] アンケートに答えると、回答に応じてタグが付き、以降の配信が変わる
- [ ] 「Day 7 へ進む」で、7日目に届くはずのメッセージが届く
- [ ] Webページで離脱操作をするとポップアップが出て、友だち追加に繋がる
- [ ] フォーム送信（応募完了）からサンクス経由で友だち追加に繋がる
- [ ] 上の6つが、**別々の画面ではなく1人のユーザーの連続した体験として**繋がっている

### 3.2 裏側が見える

- [ ] 画面の横に、現在のタグ・属性・配信履歴・進行状況が出る
- [ ] ある配信が**届いた理由**が、条件式のどこを通ったかとして見える
- [ ] ある配信が**届かなかった理由**も同じ形で見える（これが商談で一番効く）
- [ ] 「裏側あり／ユーザー画面のみ」を切り替えられる

### 3.3 複数ユーザーで差が出る

- [ ] 東京希望・大阪希望・応募済み・未応募の4人を作れる
- [ ] 同じ Day でユーザーを切り替えると、画面と配信内容が変わる
- [ ] 仮想時間は全ユーザー共通で進む（Day 7 は全員にとって Day 7）

### 3.4 案件を差し替えられる

- [ ] 新規作成・複製・保存・読み込み・削除ができる
- [ ] 会社名／配色／画像／文面／アンケート／タグ／分岐／ステップ配信を案件ごとに変えられる
- [ ] JSONでインポート／エクスポートできる
- [ ] **共通エンジンに人材業界の語彙・ルールが1つも入っていない**（機械的に検査して0件）

### 3.5 顧客に渡せる

- [ ] 単一HTMLファイルを書き出せる
- [ ] そのファイルを**ネット接続なし**・Chrome／Edge で開いて操作できる
- [ ] 編集機能・APIキー・社内メモが含まれていない（書き出し時に機械検査して混入0件）
- [ ] 重大エラーがあるシナリオは書き出せない

### 3.6 作り直さずにAIを載せられる

- [ ] AIの出力形式（シナリオ差分JSON）が決まっていて、Claude Code がそれを出せる
- [ ] 「スクショで確認できた／AIが推定した／人が承認した」が区別して保持される
- [ ] 推定のまま承認されていない内容は、顧客向けHTMLに出せない

## 4. 初期検証案件

架空の人材会社「**サンプルスタッフ株式会社（仮）**」で、下記が通ることを確認する。

```
経路A  Webサイト離脱 → ポップアップ → LINE友だち追加
経路B  求人応募 → 応募完了 → サンクスLINE誘導 → LINE友だち追加
                    ↓（合流）
        挨拶メッセージ → アンケート → 希望条件タグ付与
          → エリア別の配信分岐 → ステップ配信 → 応募・再応募
```

検証ユーザー：東京希望／大阪希望／応募済み／未応募 の4パターン。

**この案件の設定値・業務ルールは、すべて案件JSONの中に置く。**
エンジン側には一切書かない（3.4の最後の項目）。

## 5. 対象外（やらないこと）

明示的にスコープ外とする。後から「入っていると思っていた」を防ぐため。

| 対象外 | 理由 |
|---|---|
| 実際のLINE Messaging API への接続 | デモ専用。実アカウントを触るリスクを持たない |
| 実在顧客のデータの投入 | 架空・匿名化データのみ |
| LINEアプリUIの完全再現 | 機能・操作性・説明の分かりやすさを優先。見た目の忠実度は「提案資料に貼れる視認性」まで |
| スクリーンショット出力機能・画像編集機能 | OS標準の範囲で足りる |
| ツール内でのAI実行（初期版） | 初期版はClaude Codeが外で生成する。将来差し替えられる形だけ用意する |
| 有料API・外部SaaSの契約 | しない |
| 複数人同時編集・権限管理・クラウド保存 | ローカル単独で使う。将来のWebサービス化で扱う |
| 実運用の配信実行・効果測定 | シミュレーターであり運用ツールではない |
| LINE仕様の網羅的な再現（Flex Message全仕様等） | 提案説明に必要な粒度に留める |

## 6. 守る制約

- 既存ファイルを削除・上書きしない（`20260916_八十吉_通しデモ.html` は参照のみ）
- 実際のLINE APIに接続しない
- 実在顧客情報を使わない
- 有料APIや外部サービスを勝手に契約しない
- 仕様変更が必要なら、理由と影響を報告してから変える
