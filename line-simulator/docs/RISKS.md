## 1. 実装が難しい部分（難しい順）

### R-1 時間 × 複数ユーザー × 優先順位 × 停止条件（難度：高）

**何が難しいか**：Day 3 の 9:00 に、4人それぞれで複数のフローがタイマーを持っている。優先度の高いフローが配信したら低い方は見送り、応募したら停止、同じ文面は2回送らない。この組み合わせで、処理順が少しずれると結果が変わる。

**対策**
- 処理順を固定（時刻 → ユーザーID → フロー優先度 → ノードID）
- 状態はイベント列からの再計算のみ。途中で状態を直接書き換えない
- 検証案件を4人で Day 30 まで流した結果を固定ファイルとして持ち、変更のたびに比較（1文字でも変われば気づく）

### R-2 判定の木（届かなかった理由）の見せ方（難度：高）

**何が難しいか**：条件式の木をそのまま出すと、営業先には読めない。「AND」「NOT」を見せても伝わらない。

**対策**
- エンジンは木（Trace）を返すだけ。日本語化は player 側で、案件のラベル（タグ名・選択肢名）を使って文章にする
- 既定の表示は「外れた理由の1行」（例：大阪希望なので、東京向けの配信から外れました）。木は「詳しく」で開く
- Phase 4 で実画面を見て言い回しを詰める（ここはラリーが要る）

### R-3 フロー編集の操作感と条件式の入力（難度：中〜高）

**何が難しいか**：ノード10種以上の設定画面と、AND/OR/NOT の入れ子を組むGUI。作り込むほど工数が膨らむ。

**対策**
- Phase 2b は「ノードの配置・接続」＋「条件式はJSONで入力してその場で検証」に留める
- ビルダー型GUIは Phase 4。それまでの条件式は Claude Code が書いてもよい
- React Flow は薄いラッパー経由で使い、影響範囲を閉じ込める

### R-4 編集画面と営業用HTMLで結果がずれる（難度：中）

**何が難しいか**：同じロジックを2か所に書くと必ずずれる。

**対策**
- engine と player を1つずつだけ作り、両方に同じものを埋め込む
- Phase 5 の検収で「同じ操作 → 同じ結果」を確認

### R-5 汎用化の漏れ（難度：中）

**何が難しいか**：検証案件を動かしたい一心で、「応募」「エリア」などの言葉や判定がエンジンに入り込む。

**対策**
- エンジンのソースに日本語が0件であることをビルド時に検査（`check:engine`）
- CV・経路・タグはすべて案件JSONで定義した ID としてしか扱わない
- Phase 6 で別業種の案件を、エンジン無改修で動かして確かめる

## 2. 単体HTML出力の制約

| 制約 | 影響 | 対策 |
|---|---|---|
| `file://` で開くと、`fetch` で別ファイルを読めない | 案件JSON・画像を外から読めない | すべてHTMLの中に埋め込む |
| `file://` では `localStorage` が不安定 | 状態を保存できない | 保存しない。閉じたら初期状態に戻る（営業用途では問題なし） |
| 外部フォント・CDNはオフラインで切れる | 八十吉デモも Google Fonts に依存していた | システムフォント（メイリオ）のみ |
| 画像を埋め込むと重い | メール添付できない | WebP・横600pxに縮小。5MB超で警告・15MB超で中止。画像なし書き出しも用意 |
| メール添付のHTMLは、社によってはセキュリティで開けない／ブロックされる | 顧客の手元で開けない | 運用上の注意として手順書に書く（ZIPにする・共有ドライブで渡す 等）。技術では解決できない |
| HTMLの中身は誰でも読める | 社内情報が漏れる | 書き出し時に社内項目を除去し、出来上がりを機械検査 |

## 3. 仕様上の矛盾（REQUIREMENTS §3 の要約）

| # | 内容 | 推奨の解消 |
|---|---|---|
| C-1 | 無限ループ禁止 × 正当なループ | 「時間が進まず入力も待たないループ」だけをエラーにする |
| C-2 | 並行配信 × 重複配信の警告 | 静的には警告、実行時は配信台帳で実際の重複を止める |
| C-3 | 除外理由の表示 × 判定ロジック | 判定は最初から理由の木を返す |
| C-4 | 単一HTML × 画像 × オフライン | 縮小・予算・画像なしモード |
| C-10 | フロー編集が先 × 6施策が後 | Phase 2 を 2a（エンジン）／2b（画面）に分ける |

## 4. 将来拡張への影響

| 将来 | 今やっておくこと | やらないこと |
|---|---|---|
| AI内蔵 | 出所フィールドとシナリオ差分JSONを Phase 2 から入れる | AI APIの組み込み |
| Webサービス化 | エンジンを純TSに。保存はAPI経由で呼ぶ形にしておく | 認証・権限・DB |
| 業種追加 | 業種の語をエンジンに入れない。ラベルの言い換えを案件設定に持つ | 業種別のテンプレート集（必要になってから） |
| LINEの仕様変更 | LINE固有の上限は検証ルールの「警告」に集める（1か所で直せる） | 料金の自動取得 |
