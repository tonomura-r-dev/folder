# LINE施策統合シミュレーター

LINE公式アカウントの施策を、実装前に組み立てて「ユーザーに何が見えるか」と「裏で何が起きているか」を見せるツール。
設計は [`docs/`](docs/GOAL.md) を参照。

## 起動

`start.bat` をダブルクリック。ブラウザで編集ツールが開く（初回は準備に数分かかる）。
黒い画面は開いたままにしておき、終わるときは保存してから閉じる。

## いまできること（Phase 3 まで）

| 画面 | できること |
|---|---|
| **▶ デモ（動作確認）** | スマホの中のLINE・Webページを操作して、編集中の内容（未保存を含む）で動かす。はじめかた（Webサイト／直接友だち追加）→ 離脱ポップアップ・応募フォーム・サンクスのLINE誘導 → トーク・アンケート・リッチメニュー・自動応答。右の「時間」で日を進めるとステップ配信が届く。右には現在のタグ・CV・配信履歴・次の予定 |
| 案件一覧 | 新規作成・開く・複製・削除（ゴミ箱 `.trash/` へ移すだけ）・JSONから読み込み |
| シナリオ（フロー） | ノードの追加・移動・削除（Delete キー）・線を引く／繋ぎ替える・ノードごとの設定・シナリオごとの入口／優先度／停止条件 |
| 文面・タグ／CV／経路・アンケート・リッチメニュー・自動応答・Webページ・ペルソナ・説明文・案件設定 | それぞれの部品の編集 |
| 上の帯 | 保存（Ctrl+S）・履歴（過去の版に戻す・名前を付ける）・JSONで書き出し・検証結果の件数 |
| 下の帯 | 検証結果の一覧。行をクリックすると該当箇所へ移動 |

条件式（分岐・停止条件・自動応答の条件）はいまは JSON で書く。書くとその場で日本語の意味が下に出る。ブロックを組む入力は Phase 4。
画像は「案件設定」から取り込む（PNG・JPEG・GIF・WebP。案件フォルダの assets/ に保存）。
デモは1人ずつ・時間は進めるだけ。複数ユーザー・時間を戻す・自動再生・届かなかった理由の表示は Phase 4。

### 保存の決まり

- 保存のたびに、それまでの版が `projects/<案件>/history/` に残る（名前の無い版は30件まで、名前付きは消えない）
- 書き込みは一時ファイル経由なので、保存の途中で落ちても前の版が残る
- 画面を開いた後に別の場所で保存されていたら、上書きする前に確認する

## 確認コマンド

```bash
npm run check
```

型チェック → エンジンの汎用性検査（日本語・禁止API・外部 import が0件か）→ テスト の順に走る。

```bash
npm run sim -- sample-staff --until-day 30
```

検証案件を架空ユーザー4人で Day 30 まで流し、配信・分岐・停止の結果を表で出す（`--user p_osaka`・`--json` も可）。

## フォルダ

| 場所 | 中身 |
|---|---|
| `packages/engine/` | シナリオエンジン。依存ゼロ・DOMなし・日本語なし。編集ツールと営業用HTMLで同じものを使う |
| `packages/player/` | デモ画面（スマホ枠のLINE・Web・裏側）。素のDOMで作り、編集ツールと営業用HTMLで共用。判定結果・検証結果の日本語化もここ |
| `packages/editor/` | 編集ツール（React＋React Flow） |
| `projects/<案件>/project.json` | 案件（シナリオ設定） |
| `tools/` | 保存API・CLI・検査 |
| `tests/` | テスト。`acceptance.test.ts` が Phase 2a の検収条件、`store.test.ts` が保存まわり |
