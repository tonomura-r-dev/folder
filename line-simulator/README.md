# LINE施策統合シミュレーター

LINE公式アカウントの施策を、実装前に組み立てて「ユーザーに何が見えるか」と「裏で何が起きているか」を見せるツール。
設計は [`docs/`](docs/GOAL.md) を参照。

## 起動

`start.bat` をダブルクリック。ブラウザで編集ツールが開く（初回は準備に数分かかる）。
黒い画面は開いたままにしておき、終わるときは保存してから閉じる。

## いまできること（Phase 6 まで）

| 画面 | できること |
|---|---|
| **▶ デモ（動作確認）** | スマホの中のLINE・Webページを操作して、編集中の内容（未保存を含む）で動かす。はじめかた（Webサイト／直接友だち追加）→ 離脱ポップアップ・応募フォーム・サンクスのLINE誘導 → トーク・アンケート・リッチメニュー・自動応答 |

### デモの操作（上の帯）

| 段 | 操作 |
|---|---|
| ユーザー | 名前を押して切り替え／「＋ ユーザーを追加」（手で操作する・台本どおりに動く）／「× 外す」／「台本つきで全員を並べる」 |
| 時間 | 主な操作は「次の出来事 ▶」「◀ 戻る」「▶ 再生／⏸ 停止」の3つ（上に短い説明つき）。−1日・＋1時間などの細かい移動、「Day ○ ○○:○○ 移動」、「最初に戻す」（顔ぶれと台本は残る）、ユーザーの追加・外す、ほかの表示は「細かい操作 ▼」の中 |
| 再生 | 「▶ 再生」で次の出来事へ順に進む（速さ×1・×2・×5は細かい操作の中）。帯には表示中の人・台本どおりか手で操作か・再生中か停止中かを常に出す。手で操作する人がアンケートやボタン選択で回答待ちになると止まり、スマホで答えると続きから再生する |
| 表示 | **3画面**（既定）／画面＋裏側／画面のみ／資料用 16:9／資料用 16:9（3画面）。資料用は 1280×720 の枠に収まるので、Win+Shift+S で切り取ってそのままスライドに貼れる |

- 全員が同じ時計で動き、タグ・回答・配信履歴・シナリオの進み具合は一人ずつ別に持つ
- 時間を戻しても、同じ操作なら同じ結果になる。**過去の時点から手で操作すると、その人のそれより後の操作は消える**（帯に注意が出る）
- 台本つきの人を手で操作すると、その人は台本から外れる

### 3画面（①ユーザーが見る画面 ②裏側の処理 ③CVまでの道筋）

①でスマホを操作すると、②のタグ・判定・配信履歴と、③の「いまどこにいるか」が同時に変わる。
画面の幅に合わせて 3列 → 2列（①の右に②③）→ 1列 に組み替わる（1366px のノートPCでも3列）。

①②は**選んだ1人**の画面と内部状態だけを出し、別の人に何か起きても勝手に切り替えない（切り替えるのはユーザー一覧か、③の行の「この人を①②に表示する」）。
「次の出来事 ▶」で別の人の出来事に進んだときは、上の帯に「別のユーザーの出来事です（○○さん：アンケート回答）」と出る。

③は上から4段（「いま起きたこと」＝いまの時刻に全員に起きたことを、表側＝緑・裏側＝灰で。表示中の人が先頭）：

| 段 | 中身 |
|---|---|
| 現在地 | 選んでいる人の段階・GOALまでの状況と**次にすること**（手で操作／台本が操作／配信を待つ／完了／停止中）。指している①のボタンは橙の枠で光る。下へスクロールしても上に残る |
| CVまでのフロー | 下の表のフローチャート |
| いま起きたこと | いまの時刻（無ければ直前）の出来事を全員分。ほかの人は「この人を表示」で切り替えられる |
| 全ユーザーの時系列 | 全員の出来事を時刻順に、**表側**（LINE・Web画面で見えること）と**裏側**（タグ・シナリオ開始・分岐・待機・停止・CV）で。選んでいる人は濃く、ほかの人は薄く。「いま」の線より下は**予定**（操作がない場合・台本どおりの場合）。行を押すと細かい処理まで展開。「全体の次の出来事」で、次に進む時刻に誰に何が起きるかが分かる |

時系列は固定の台本ではなく、エンジンの実行結果（行動・配信・判定・タグ・CV）から毎回作る。時間を戻して答えを変えると作り直される。
16:9（投影用）は、上の帯を1段に詰め（ユーザーはプルダウン）、見える高さにも合わせて1画面に収める（1366×768で約0.97倍、1920×1080で約1.4倍）。③は、次にすること・現在地の前後とGOAL・直前と次の出来事だけを出す（フローチャートは縮めない）。

文面の吹き出しに「カルーセル」（横に並ぶカード）を使える。①では左右のボタン・点・ドラッグ（スワイプ）で送れて、見たカードは「カードを見た」として③の時系列に残る（条件式の「やったこと」でも使える）。②の「いまの状態」には、届いたカルーセルごとに、その中身になった理由（直前の分岐の条件）と、見たカード・押したボタンの数が出る。
リッチメニューのセルを「メニューを切り替える」にすると、2タブ構成のメニューを作れる（いま開いているタブは「動作なし」にすると、色付きのタブで出る）。いちばん押してほしい項目は「目立たせる（emphasis）」で色付きにできる。

運用寄りの流れ（求人の検索・勤務連絡・再応募など）のために、次も使える。
- Webページの「一覧（絞り込みつき）」：エリア・会場などの軸で①の中で絞り込める。選択肢にタグを結び付けると、LINEから開いたときに希望条件で絞り込んだ状態で開く。締切を過ぎた項目は出ない。絞り込みは③の時系列に残る
- 待ち方「全員共通の日時」：企画配信（例：11/9 12:00）やイベント前日のリマインドのように、友だち追加の日に関係なく決まった日時に送る。日時を過ぎてから来た人は待たずに「過ぎていた」の出口へ
- アンケートの「聞き直す」：前の回答を消して1問目から聞き直す（メニューの「希望条件を変える」など）。タグは選び直した選択肢で入れ替わる
- CVの種類「運営側の登録（stage）」：勤務確定・勤務完了のように運営側が管理画面で登録する段階。CVの数に入れず、②は「〇〇側の登録」、③は「◆ 〇〇が「勤務確定」を登録」と別の色で出す。「何度でも記録できる」にすると、イベントごとに何度でも登録できる
- サンクスLINE誘導の「入力欄への引き継ぎ（prefill）」：押した直後、トークの入力欄にフォームの内容が入る。送るかは本人が決める（自動の本人照合はしない）
- CVまでの道筋の「くり返し（loopTo）」：GOALのあとに「↺ 〇〇へ戻る」とこの人の回数を出す（再応募 → 勤務確定 など）
- CVまでの道筋の「主要な工程（key）」：資料用16:9の③でも「⋮ ○段」にまとめず、いつも出す（応募 → 登録 → 勤務 → 再応募 など）。その案件では1段を低くし、下の「出来事」の枠を残りの高さに縮める

ペルソナに「人物名」（架空）を入れると、文面の {{user.name}} は人物名になり、画面は「人物名＠役割」で出る。
②の「次の段階へ進める」ボタン名はCVごとに設定できる（無ければ「○○へ」。済んだ段階は押せない）。
はじめかたの入口は、案件設定の「はじめかたに大きく出す入口」で数個に絞れる（ほかのページ・経路は折りたたみに残る）。

③のフローチャートは、営業先に流れを説明するための図（編集用の詳しいフロー図ではない）。

| 表示 | 中身 |
|---|---|
| START／GOAL | 最初の段（紺）と、最後のCV地点（橙）を色付きで |
| 施策（四角） | 施策名と、紐づく文面の1〜3行。通った箱は「✓ 通過」、いまいる箱に「現在ここ」 |
| 分岐（ひし形） | 問い（例：地域選択済み？）と、矢印ごとの行き先（東京／大阪／未回答）。②と同じ条件式で「この人のルート」を判定 |
| 追加候補（点線） | 今回は採用していないが提案できる施策。表示だけで、シナリオにも配信にも影響しない |
| Lステップ | ◎単体で可／○条件あり／△外部ツール・Web側の実装が必要／？未確認（未確認を「可」と出さない） |
| 次にすること | 選んでいる人の次の操作・次の配信（シミュレーションの結果から）／回答待ち／ブロック中・停止の理由 |

- 箱を押すと詳細：文面の全文（LINEの見た目・ボタンの動作つき）・タイミング・配信対象・止める条件・目的・この人への配信状況。ひし形は行き先ごとの条件と、この人が当てはまるか
- 文面は③に二重登録しない。シナリオのノード（と自動応答の文面）を参照するので、文面を直すと①と③の両方が変わる
- −／＋／幅に合わせる で拡大縮小
- 中身は案件の「CVまでの道筋」で作る（施策名・目的・紐づくノード・分岐の問いと行き先・実現性・追加候補）。未設定の案件は、シナリオの一覧とCVから簡易表示を作る
- AI提案で足した施策・候補も、承認すれば同じ仕組みで表示される（承認前は書き出せない）

### 裏側（②）

| タブ | 中身 |
|---|---|
| （上の説明カード） | いま起きたことの説明（案件の「説明文」） |
| いまの状態 | 友だちかどうか・経路・CV・属性・タグ・回答・シナリオの進み具合。「次の段階へ進める」（例：応募へ。済んだ段階は押せない）・「ブロックする」で、各段階の配信と裏側を確かめられる |
| なぜ | 届いた・届かなかった・分岐で進まなかった・止めた、を理由つきで。▼で条件の木（✗ が当てはまらなかった条件と、実際の値） |
| 配信履歴 | この人とデモ全員の通数。案件設定で無料通数を入れると「無料○通のうち△通（目安）」 |
| 誰に届く？ | シナリオの文面 × ユーザーの表。✓ 届いた／✗ 届かない理由／■ 停止／— 入っていない・別ルート |
| 案件一覧 | 新規作成・開く・複製・削除（ゴミ箱 `.trash/` へ移すだけ）・JSONから読み込み |
| シナリオ（フロー） | ノードの追加・移動・削除（Delete キー）・線を引く／繋ぎ替える・ノードごとの設定・シナリオごとの入口／優先度／停止条件 |
| 文面・タグ／CV／経路・アンケート・リッチメニュー・自動応答・Webページ・ペルソナ・説明文・CVまでの道筋・案件設定 | それぞれの部品の編集 |
| 上の帯 | 保存（Ctrl+S）・履歴（過去の版に戻す・名前を付ける）・JSONで書き出し・検証結果の件数 |
| 下の帯 | 検証結果の一覧。行をクリックすると該当箇所へ移動 |

条件式（分岐・停止条件・自動応答の条件）は画面で組み立てる：「次のすべてを満たす（AND）／どれかを満たす（OR）」のグループに条件を入れ、どれにも「ではない（NOT）」を付けられる。「JSON」に切り替えて直接書くこともできる。下に日本語の意味が出る。
画像は「案件設定」から取り込む（PNG・JPEG・GIF・WebP。案件フォルダの assets/ に保存）。
検証の警告には、ペルソナを台本どおり30日流しても誰も入らないシナリオも出る（重大エラーが無いとき）。

### 保存の決まり

- 保存のたびに、それまでの版が `projects/<案件>/history/` に残る（名前の無い版は30件まで、名前付きは消えない）
- 書き込みは一時ファイル経由なので、保存の途中で落ちても前の版が残る
- 画面を開いた後に別の場所で保存されていたら、上書きする前に確認する

## 営業用HTMLの書き出し（Phase 5）

社外にも渡せる、**ネット接続なし・インストール不要**で動く単一のHTMLを書き出す。

- **編集ツールから**：上の帯の「営業用HTMLを書き出す」→「架空または匿名化したものだけです」にチェック →「書き出す」。
  保存済みの内容が **Downloads 直下** に `<案件名>_デモ_YYYYMMDD.html` で出る（同じ名前があれば `_2` を付け、上書きしない）
- **コマンドから**：

```bash
npm run export -- sample-staff --confirm-fictional
```

書き出す前に検証し、**重大エラーがあれば書き出さない**（警告だけなら書き出す）。HTMLは5MBを超えると警告、15MBを超えると書き出さない。
大きい画像は横800pxのWebPに縮めて埋め込む。社内メモ（`_internal`）・AIの出所メモ（`prov`）は取り除き、出来上がったHTMLに社内メモ・APIキーらしき文字列・外部の読み込み・編集ツールのコードが無いことを確かめてから保存する。
HTMLには通信を禁止する設定が入っていて、外部のファイルやURLを一切読まない。

開いたときの状態は「案件設定 → デモの始まり方」で選ぶ（1人を手で操作〈標準〉／台本のあるペルソナ全員）。

## 既存アカウントのスクショからシナリオ案を作る（Phase 6）

詳しくは `docs/AI_WORKFLOW.md`。編集ツールにAIは入れていない。解析は Claude Code が行う。

1. 編集ツールで案件を作り、スクショを `projects/<案件>/screenshots/` に置く（リポジトリには入らない）
2. Claude Code に「`<案件>` のスクショからシナリオ案を作って」と頼む（スキル `line-sim-screens`）。
   提案が `projects/<案件>/patches/` に保存され、`npm run patch:check -- <案件> <ファイル名>` で検査される
3. 編集ツール → 「AI提案（スクショから）」→ 提案ファイルを選ぶ → 採る提案にチェック →「選んだ提案を下書きに取り込む」→ 保存
4. 「承認待ち」の一覧で、1件ずつ「開いて直す」「承認」「却下」（まとめて「すべて承認」も可）。
   **承認待ち（AI推定）が1件でも残っていると、営業用HTMLは書き出せない**
5. 「▶ デモ」で動きを確かめてから書き出す

一覧・フロー図・詳細の色バッジで「確認済み（スクショに写っていた）／AI推定（承認待ち）／承認済み」が分かる。
実例は `examples/sample-beauty/`（架空の美容サロン）。

## 実在の企業向けデモ案件

提案資料から作る企業別のデモは、`projects/client-*/` に置く。**このフォルダはGitに入れない**（.gitignore 済み）。
仮設定や外部実装が必要な箇所は、各フォルダの `NOTES.md` に書く。テスト（`tests/clients.test.ts`）は、案件が手元に無ければ飛ばす。
30日より先（休眠掘り起こし等）を自動再生で見せたい案件は、`settings.demoEndDay`（1〜365）で再生の終わりを延ばす。

## 確認コマンド

```bash
npm run check
```

型チェック → エンジンの汎用性検査（日本語・禁止API・外部 import が0件か）→ テスト の順に走る。

```bash
npm run sim -- sample-staff --until-day 30
```

検証案件を架空ユーザー4人で Day 30 まで流し、配信・分岐・停止の結果を表で出す（`--user p_osaka`・`--json` も可）。
