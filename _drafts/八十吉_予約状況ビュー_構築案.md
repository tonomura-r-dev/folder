# 八十吉：予約状況ビュー 構築案（流れの「3」を埋める部品）

作成：2026-09-07
**前提の流れ（殿村さん指定・ここから動かさない）**

```
1   （LINE）ユーザ → 店（パフォ）      意思表明（指名）
2   （LINE）パフォ → ユーザ            一時返信（情報確認）。予約確定ではない
2.5 （LINE）パフォ → ユーザ            ご予約可能タイミングはこちら。早い者勝ち
3   （LINE）店が見る → ユーザ-パフォ    条件をユーザーに提示
    （Airレジ）パフォ → 店の状況を把握   条件をユーザーに提示
4   （食べログ等の予約ツール）ユーザ → 予約 ＋ 予約日時をLINEで送付
5   （LINE＋食べログ）店 → 予約が取れているか確認
```

詰まっているのは **3の2行目「パフォがAirレジ（レストランボード）で店の状況を把握する」**。
ログインを渡すと売上が見える。権限設定でも切れなかった（殿村さん確認済み）。HPは作らない。手入力もしない。

## 構築するもの：予約状況ビュー（読み取り専用・ログイン不要・売上を通さない）

```
レストランボード ──予約通知メール──▶ Gmail ──▶ GAS（5分おきに読む）──▶ スプレッドシート「予約状況」
                                                                          │
パフォーマー ◀── LINEリッチメニュー「空き状況」 ◀── LIFF（日別：予約一覧・残席）◀─┘
```

- **入口はレストランボードの「メール通知設定」**。予約が入る／変わるたびに店宛てにメールが届く機能（標準・無料）。
  このメールには予約の日時・人数・名前は載るが、**売上は載らない**。だからこれを情報源にする。
- GASがそのメールを読んで、スプレッドシートに「日付／時間／人数／名前／媒体／状態」で1行ずつ積む。
- パフォーマーはLINEのリッチメニュー「空き状況」を押す → LIFFで **日別の予約一覧と残席**（総席数 − 予約人数）が見える。
  レストランボードには一切触らない。売上はどこにも出てこない。
- **5もこれで閉じる**：4でユーザが食べログで予約 → 台帳に入る → 通知メール → シート → 店もパフォも「取れている」をLINE内で確認できる。

## 流れの各ステップと、部品の対応

| 流れ | 誰が | 使うもの | 構築 |
|---|---|---|---|
| 1 意思表明 | ユーザ | LINEチャット（あいさつ＋記入フォーマット） | 既存（デッキP24②） |
| 2 一時返信 | パフォ | LINEチャット 定型文 | 既存 |
| 2.5 可能タイミング | パフォ | LINEチャット 定型文＋**予約状況ビュー**で残席を見てから送る | **ビュー** |
| 3 条件提示 | パフォ | **予約状況ビュー**で店の状況を把握 → LINEで条件提示 | **ビュー** |
| 4 本予約 | ユーザ | 食べログ等の予約ツール → 予約日時をLINEで報告 | 既存（デッキP10のリンク添付） |
| 5 確認 | 店・パフォ | **予約状況ビュー**に4の予約が載っているか見る | **ビュー** |

## 部品の中身

| 部品 | 中身 | 費用 |
|---|---|---|
| レストランボード メール通知 | 設定画面でオン。通知先＝GAS用のGmailアドレス | 0円 |
| Gmail（GAS用） | 通知メールの受け口。店のアドレスは変えない（転送で足りる） | 0円 |
| GAS | ①5分おきにメールを読んでシートへ ②LIFFからの読み取りAPI（`getStatus(date)`） | 0円 |
| スプレッドシート | 「予約」「設定（総席数・営業時間）」「ログ」の3シート | 0円 |
| LIFF（HTML1枚） | 日付を選ぶ → 予約一覧＋残席。GitHub Pagesに置く | 0円 |
| LINE公式 | リッチメニューに「空き状況」を追加（パフォーマー向け。お客様には見せない配置にするか、別のリッチメニューを当てる） | 0円 |

通数はゼロ（ビューは見に行くだけで配信しない）。

## 成り立つための前提（1つ）

**レストランボードの通知メールに、食べログ経由（サイトコントローラー）と電話の予約も載ること。**
公式FAQに明記されているのは「即予約・リクエスト予約の受付通知」と「翌日来店予定の一覧」。
ネット予約しか載らないなら、ビューの残席は実際より多く出る。
→ 確認方法は「電話予約を1件入れて、メールが来るか見る」だけ。今やらなくていいが、着手前には要る。

## それ以外の名案（1つだけ）

サイトコントローラー側にスタッフ用の閲覧権限があれば、構築ゼロでパフォーマーに空き状況を見せられる（食べログ・ホットペッパーの予約はSCが握っているため）。
名前が分かったときに10分で調べられる。それまではこの構築案で進める。
