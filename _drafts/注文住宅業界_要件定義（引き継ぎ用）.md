## 5. 判断保留の論点

### 5.1 【未決】S05・S06（広告2枚）を残すか

**論点：** この資料は「LINEOA運用」の提案。S05（検索広告のCPC推移）とS06（広告実績CVR＋広告審査）は
**Web広告全般の話**で、運用の話から遠い。

**入れた理由：** スキル §6.5 の最上級FMT構成に「CPC推移」「広告実績CVR」「広告審査面の懸念」が
必須項目として指定されているため。**意図的に入れたもので事故ではない。**

**選択肢**

| 案 | 内容 | 影響 |
|---|---|---|
| A | このまま残す | §6.5を満たす。S05は「広告を増やす戦い方には天井がある→だからLINEOA」という導入の理由付けとして機能し、S07以降につながる |
| B | S06だけ落とす／差し替える | 広告審査は運用から最も遠い。ここだけ抜くのが落としどころ |
| C | S05・S06とも削除 | 34枚になる。LINEOA運用に純化するが §6.5 の3項目が欠ける |

**注意：** LINE広告・CPF（友だち追加広告）は**友だち追加動線＝LINEOA運用の一部**なので、
これを消すと施策が成立しない。S03/S18/S20/S24/S25/S29/S16 に登場するが**残すこと**。

### 5.2 【要検討】14日ステップの初回配信タイミング

現行案は Day0 → Day1 → Day3 → Day6 → Day9 → Day11 → Day14。

一方、LIFULL HOME'S の公式事例に
**「友だち追加から1週間後に初回メッセージを送るパターンBのほうがクリック率が高かった」**
という記載がある。

ただしLIFULLは**不動産ポータル**（賃貸・売買）で、注文住宅とは検討の質が違う。
注文住宅は検討10ヶ月なので、初期の関係構築を厚くする現行案にも合理性がある。

**→ そのまま採用せず、A/B検証項目として扱うのが妥当。**

- **出典のない数値を書かない。** 業界指標／自社実績／仮置きを混ぜず、ラベルを分ける
  - `業界水準` = 公開情報・業界一般値
  - `弊社実績` = DYMの支援実績
  - `★想定値` = 根拠を置いた試算（**3つまで**）
- **競合は実名を出すなら実データで。** 未確認なら「仮説」バッジ、または破線の差込枠にする
- **1枚1メッセージ／1カード3〜4行／1行20〜25字**
- **相関を因果と言い切らない**（例：配信数と友だち増加率の関係）
- 最後に必ず **【要確認リスト】**（① 置いた前提★／② 社内・上司確認／③ 人が集める素材）
- **要求する情報の種類を増やさない。**②③は 4.3 の5種に限定する

### 6.1 出典を混ぜてはいけない具体例

| 主張 | 正しいラベル |
|---|---|
| LINE国内月間利用者数 1億人突破（2025年12月末） | LINEヤフー公式 |

| 「LINE経由で来店率40〜50%改善」 | **DYM支援実績。**公式値ではない |

### 8.1 修正するときどこを触るか

| 直したいもの | 触る場所 |
|---|---|
| 新規再構築した14枚の文言・レイアウト | `build_chumon_jutaku.py` の `# ==== S05 ====` 等の各ブロック |
| FMT流用スライドに残った他業種の語 | `build_chumon_jutaku.py` の `REPLACE` リスト |
| スライドの採否・並び | ベースが36枚固定。**削除はできるが追加はしない** |
| 配色 | ファイル先頭の定数（`TNAVY` `NAVY` `ORANGE` `INK` …） |

### 8.2 踏んだ落とし穴（`_build/README.md` と共通）

1. **`put_text()` は必ず `reset_tf()` を通す。** 既存シェイプに直接書くと**追記**になって文字が混ざる
2. **スライドの新規追加はしない。** パート名重複で壊れることがある
3. **`REPLACE` は順番が効く（先勝ち）。** 長い文字列を先に置く。
   例：「リピート率、クロスセル率、客単価を…」を先に置かないと、
   個別置換が先に走って長い方がマッチしなくなる
4. **FMTは別業種（EC・人材）の提案書。** クロスセル／転職／求人／〇〇診断 等の残骸が必ず残る。
   ビルド後に必ず正規表現で残骸スキャンをかける

## 10. 環境の落とし穴（クラウド／claude.ai/code）

引き継ぎ先が同じクラウド環境なら、先に以下を潰しておくと詰まらない。

| 症状 | 原因 | 対処 |
|---|---|---|
| `soffice` が「source file could not be loaded」 | `libreoffice-impress` / `libreoffice-calc` が**未導入** | `apt-get update && apt-get install -y libreoffice-impress libreoffice-calc` |
| `pdftoppm: command not found` | poppler が無い | `_build/qa_render.py` が **PyMuPDF に自動フォールバック**する（対応済） |
| recalc.py がタイムアウト | 上記の calc 未導入 or soffice のゾンビプロセス | calc を入れる／`pkill -9 -f soffice` |
| `page.line.me` `lineoa.jp` `lycbiz.com` `jhf.go.jp` が見られない | **egress ポリシーでブロック** | **PC側で取得するしかない**（→ 4.2 / 4.4） |
