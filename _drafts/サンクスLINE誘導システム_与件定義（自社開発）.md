**図A　システムの動き（G6）**

```
完了画面（自動で飛ぶ／飛べないときはボタン）
 │
 ├─ 完全連携 … OAと同じプロバイダにLINEログインを作れる案件
 │    └ LIFF → 許可 → 友だち追加 → DBに保存
 │
 └─ 誘導のみ … 作れない案件
      └ 友だち追加URL（lin.ee/…）へジャンプ。保存なし
```

**図B　紐付けの深さ（G7）**

```
レベル1 個別紐付け … IDを渡せる案件
 └ DB：userId × クライアントID × 注文ID／申込ID

レベル2 セグメント紐付け … IDを渡せない案件
 └ DB：userId × クライアントID × CVページ識別（例：LP_A／資料請求）
```

## 2. 公式仕様で確認済みの制約（LINE Developers公式ドキュメントで確認・2026-09-30）

| # | 制約 | 与件への影響 |
|---|---|---|
| C1 | ボットリンクは**2モードとも、ユーザーが友だち追加を選べる（断れる）**。自動では追加されない | 追加率は100%にならない。**追加した／しなかったを判定**し、しなかった人の**再誘導**を用意する |
| C2 | LINEログインチャネル（LIFFの親）と、OAに関連付いたMessaging APIチャネルは**同じプロバイダ**でないとリンクできない。**1ログインチャネル＝1 OA** | **OAごとに**、そのOAと同じプロバイダにログインチャネル＋LIFFを作る。OAはMessaging APIを有効化している必要がある（送信機能を使わなくても） |
| C3 | リンク設定をする人は、ログインチャネルの**Admin権限**とOAの**管理者権限**の両方が必要 | 導入時にクライアント側の権限付与が要る |
| C4 | userIdは**プロバイダごとに別の値**。同じプロバイダなら、ログインチャネルでもMessaging APIでも同じ値。**プロバイダをまたいだ突き合わせ方法は、公式の該当ページに記載なし** | 別プロバイダ経由で取ったuserIdは、OA側のuserIdと突き合わせられない前提で考える |
| C5 | OAでMessaging APIを有効にするとき**プロバイダを選ぶ（作成も可）**。**一度選ぶと、後から別のプロバイダに変更できない** | 「DYMのプロバイダで有効化する」案件は、クライアントが後でDYMから離れても、Messaging API側はDYMのプロバイダに残る。**事前の了承が要る** |
| C6 | **認証プロバイダ**配下だと、友だち追加オプション（bot_prompt=normal）が**最初からON**になる | 追加率に効く可能性。認証プロバイダは代理店経由で申請する形（参考資料p.40）→ D9 |

## 4. 基本の流れ（貼られた案をG8に合わせて修正。D1で現行を確認したら見直す）

```
完了画面 … JSタグが自動でLIFFへ移動（待ち時間あり）／飛べないときはボタン
 ▼
LIFF … LINEログイン → 許可 → 友だち追加の確認
 │ IDトークン
 ▼
自社サーバー … IDトークンを検証して userId を確定
 ▼
DB … userId × client_id × ID（日時つき）
 ▼
完了表示 → LIFFを閉じる
```

**貼ってもらった案（Gemini出力）のうち、そのまま与件にしない点**

- 「ボットリンクで自動的に友だち追加」は誤り（C1）
- 「クライアントごとにLIFF IDを発行するだけ」では足りない。**そのOAと同じプロバイダで**作る必要がある（C2）
- フロントから`userId`と`order_id`をそのままPOSTするコードは**改ざんできる**（D6）
- LIFFのURLが`https://line.me`になっている（貼り付け時に欠けたと思われる）。正しくは`https://liff.line.me/{LIFF ID}?…`
- EC（購入）前提で書かれている。フォーム/LPも対象（G5）

## 5. 参考資料：CRM PLUS on LINE（ソーシャルPLUS社・Shopifyアプリ／2025年8月更新・45ページ）

殿村さんがチャットに添付。**現行システムそのものかは不明**。サンクスページからLINE連携する型（p.14）が、私たちが作るものと同じ型。**Shopify専用の資料なので、Shopify固有の話（会員ID・アプリ・チェックアウトエディタ）を、私たちの要件の前提にしない。**

**サンクスページ連携（p.14・全プラン対象）**

```
サンクスページ
 │ ボタン「LINEで連携する」
 ▼
LINEの許可画面 …「許可する」
 ▼
友だち追加画面 …「友だちを追加」
 ▼
サイトに戻る
   └ 裏側：LINEのuserId × 会員ID を保存
```

- 何か：Shopify専用アプリ。LINE ID ⇄ Shopify会員ID を連携する（p.8）。3,000ストア以上。LINEヤフーの代理店（p.4・6）
- 友だち追加：許可→追加の2回タップ（p.13・14）。代理店経由の申請で「自動友だち追加（デフォルトON）」（p.37）
- 代理店経由の申請：既存OAは商流変更（毎月15日締め・翌月初反映）→ プロバイダ／チャネル作成 → 認証プロバイダ申請 → Profile+申請。**10〜15営業日**（p.40）。新規OAは代理店経由で申込（p.41）
- 設置：追加スクリプトの貼り付け方式は2025/8/28で終了。チェックアウトエディタ方式へ（p.14）
- 店舗：会員登録用のQR・URLを発行できる（p.44）。Web経由のQR＝私たちの「固定QR＋レベル2」と同じ型
- 料金：アプリ月額 $0〜$200+（連携ユーザー数で従量）（p.31〜33）。LINE公式アカウントの代理店費用は別（p.39）
- 本件では使わない機能：セグメント配信・カゴ落ち／閲覧リマインド・通知メッセージ・Shopify Flow連携（p.16〜29）
- 原本はチャット添付（リポジトリには入れていない。必要なら再添付）
