## 2. 公式仕様で確認済みの制約（LINE Developers公式ドキュメントで確認・2026-09-30）

| # | 制約 | 与件への影響 |
|---|---|---|
| C1 | ボットリンクは**2モードとも、ユーザーが友だち追加を選べる（断れる）**。自動では追加されない | 追加率は100%にならない。**追加した／しなかったを判定**し、しなかった人の**再誘導**を用意する |
| C2 | LINEログインチャネル（LIFFの親）と、OAに関連付いたMessaging APIチャネルは**同じプロバイダ**でないとリンクできない。**1ログインチャネル＝1 OA** | **OAごとに**、そのOAと同じプロバイダにログインチャネル＋LIFFを作る。OAはMessaging APIを有効化している必要がある（送信機能を使わなくても） |
| C3 | リンク設定をする人は、ログインチャネルの**Admin権限**とOAの**管理者権限**の両方が必要 | 導入時にクライアント側の権限付与が要る |
| C4 | userIdは**プロバイダごとに別の値**。同じプロバイダなら、ログインチャネルでもMessaging APIでも同じ値。**プロバイダをまたいだ突き合わせ方法は、公式の該当ページに記載なし** | 別プロバイダ経由で取ったuserIdは、OA側のuserIdと突き合わせられない前提で考える |
| C5 | OAでMessaging APIを有効にするとき**プロバイダを選ぶ（作成も可）**。**一度選ぶと、後から別のプロバイダに変更できない** | D2のパターンB・Cは、OAのMessaging API側がDYMのプロバイダに固定される |

### D2. OAの扱いが案件ごとに違うとき、システムはどう動くか

| パターン | 状況 | 友だち追加の誘導 | データの紐付け |
|---|---|---|---|
| A | 既存OA。Messaging APIは**有効化済み**で、そのプロバイダの管理者権限をもらえる | ○ | ○ |
| B | 既存OA。Messaging APIが**未有効** → **DYMのプロバイダ**で有効化する | ○ | ○　⚠️選んだプロバイダは後から変更不可（C5）。クライアントがDYMから離れても、Messaging API側はDYMのプロバイダに残る |
| C | **新規OA**をDYMのプロバイダで作る | ○ | ○　（Bと同じ注意） |
| D | 既存OA。Messaging APIは有効化済みだが、**そのプロバイダに入れない**（ツール会社のプロバイダなど） | ○（友だち追加URL／QRへの誘導のみ） | ✕（C4。**要確認**） |

決めること：Dを「誘導だけ」で割り切るか／導入の条件として権限付与を必須にするか。Bを使うときの同意をどう取るか。
**案：Dは誘導のみ。紐付けはA・B・Cの案件だけ。B・Cはクライアントに「DYMのプロバイダで管理する」ことを事前に了承してもらう。**

### D3. 紐付けキー（導入先タイプ別）

「何と何を紐付けるか」は、完了画面が何を出せるかで決まる。

| 導入先 | キーの候補 | 課題 |
|---|---|---|
| ECの購入完了 | 注文ID（URLで渡す） | URLは書き換えられる → 署名が要る（D6） |
| フォーム/LP | 申込ID | 多くのフォームは完了画面にIDを出せない |
| 店舗（POS） | レシート番号／QR | レシートごとに違うQRは難しい |

決めること：IDを渡せない案件はどうするか。
**案：IDを渡せる案件は個別に紐付け。渡せない案件は「どの案件・どのCV経由か」だけを紐付け（個人の特定はしない）。**

## 4. 貼ってもらった案（Gemini出力）の扱い

方向性（LIFF＋JS、クライアントごとにチャネル）は採用。**そのまま与件にしない点：**

- 「ボットリンクで自動的に友だち追加」は誤り（C1）
- 「クライアントごとにLIFF IDを発行するだけ」では足りない。**そのOAと同じプロバイダで**作る必要がある（C2）
- フロントから`userId`と`order_id`をそのままPOSTするコードは**改ざんできる**（D6）
- LIFFのURLが`https://line.me`になっている（貼り付け時に欠けたと思われる）。正しくは`https://liff.line.me/{LIFF ID}?…`
- EC（購入）前提で書かれている。DYMの案件はフォーム/LPが中心（G5）

**基本の流れ（貼られた案。D1で現行を確認したら見直す）**

1. 完了画面のボタン（URLに client_id・注文IDなどを付ける）
2. LIFFが開く → LINEログイン → 友だち追加の確認（ボットリンク）
3. LIFFがuserIdを取得してサーバーへ送る
4. サーバーが保存（client_id／userId／注文ID／日時）
5. 完了表示 → LIFFを閉じてトークへ
