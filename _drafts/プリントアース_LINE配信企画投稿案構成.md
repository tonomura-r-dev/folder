## 1. 企画投稿案カレンダー（9月〜翌8月）

形式は「◯月：企画（参照データ）」。**参照データ欄の「要検証」は、自社売上データかGoogleトレンドで裏取りしてから提案に出す。**

| 月 | 企画 | 参照データ |
|---|---|---|
| **9月** | **秋の販促応援キャンペーン**（サマー終了の受け皿）＋**年賀状早割スタート告知** | 要検証：昨年9月の商材別売上／「年賀状 印刷」検索の立ち上がり時期 |
| 10月 | 展示会・イベント繁忙期 → チラシ・パンフ・のぼり訴求／年賀状早割 第2弾 | 要検証：秋の展示会開催数、昨年10月のチラシ受注 |
| 11月 | 年賀状本番＋**喪中はがき**（別ニーズ・別導線） | 要検証：喪中はがきの取扱有無 |
| 12月 | **年賀状 最終入稿日カウントダウン**／年末挨拶状 | 納期カレンダー（自社データ・確定情報） |
| 1月 | 寒中見舞い／**新年度に向けた名刺・会社案内の準備告知** | 要検証：1月の受注谷の深さ |
| 2月 | **年度末の名刺・封筒 先行手配**（異動・新入社員分） | 業界水準：4月入社・異動で名刺需要が集中 |
| 3月 | 新年度直前の駆け込み（名刺・パンフ）／卒業・入学 | 要検証：3月の駆け込み比率 |
| 4月 | 新年度スタート → 名刺追加・増刷／新規会員向けオファー | 業界水準 |
| 5月 | 夏の販促準備／決算・株主総会まわりの冊子 | 要検証 |
| 6月 | 夏キャンペーン予告／暑中見舞い | 要検証 |
| 7月 | 夏本番セール／**お盆前の納期告知** | 納期カレンダー（自社データ） |
| 8月 | サマーキャンペーン（今年実施済み＝実績あり）／お盆休み納期注意 | **自社実績：2026年サマーキャンペーン** |

**設計の軸**
1. **年賀状（9〜12月）と名刺（1〜4月）で年2つの山**を作り、その谷（5〜7月）をキャンペーンで埋める。
2. **納期は毎月の定番ネタ**。「いつまでに入稿すれば間に合うか」は常に開封される。
3. スタンプカード【第一段】が走っているので、**第二段以降を年間の山に合わせて設計**する。

## 3. 今月（9月）の即断分 ― 新CRと連動させる

今夜差し替える新CRの主訴求が、そのまま9月の配信テーマになる。**選択肢は2つ。**

| 案 | 主訴求 | 向くケース |
|---|---|---|
| **A：秋の販促応援** | 「秋の集客、まだ間に合う」チラシ・フライヤー中心 | 年賀状を扱っていない／扱いが小さい場合 |
| **B：年賀状早割** | 「早いほど安い」年賀状 早期割引スタート | 年賀状を扱っている場合。**9月は早割告知の最適期** |

→ **年賀状の取扱いがあるならBを推奨。**単価と季節需要の山が最も大きいため。
→ Aで走る場合も、10月にBを重ねられるようスタンプカード第二段を10月開始で設計する。
