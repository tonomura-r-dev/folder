## 1. いちばん大事な3点（10/20の案に効く所）

| 聞きたかったこと | 答え | 根拠 |

| 導入前からの友だちは、いつLステップに入るか | **自動では入らない。友だちが「何か動く」と入る。** 動く＝トークに文を送る／Lステップで設定したボタン・リッチメニューを押す／回答フォームに答える。**URLを開くだけのリンクを押しても入らない**（解説記事に「URLリンクだと反映されません」と明記） | 公式ブログ「友だちをLステップに認識させる方法3選」＋解説記事2本 |

| Lステップから配信するときの絞り込み | **タグ・友だち情報（回答フォームで取った値）・シナリオなどで絞れる。** 「流入経路」「対応マーク」「登録日」「最終反応日」でも絞れる（10/20 管理画面で確認・下の1b） | 公式ブログ「セグメント配信とは」＋解説記事 |

## 2. 機能の一覧（プランごと）

| 機能 | 何ができるか | 使えるプラン |
|---|---|---|
| 一斉配信（セグメント配信） | タグ・友だち情報などで絞って送る。1人でも絞れる（OAMの属性フィルターは推定属性・3日前のデータ・人数の下限あり） | スタート以上（記事による） |
| 自動応答 | キーワードに反応して返事・タグ付け・シナリオ開始などを自動実行 | フリー以上 |
| シナリオ配信（ステップ配信） | 友だち追加や条件を起点に、決めた間隔で順番に送る | プロ以上 |
| リマインダ配信 | 予約日などを起点に、前日・当日に送る | スタンダード以上（要確認） |
| URLクリック測定 | 短縮URLで、誰が押したかを測る・押した人にタグを付ける。**Lステップ経由の配信でしか測れない**（OAMから送った配信のリンクは測れない） | スタンダード以上 |
| 回答フォーム（アンケート） | 質問に答えてもらい、答えを友だち情報に保存（都道府県のプルダウンあり）。**2026年5月の新フォームはLINEログインが必須** | スタート以上（要確認） |
| リッチメニュー／セグメントリッチメニュー | タップ時の動作＝URLを開く／ユーザーメッセージ送信（友だちが文を送る）／テキスト送信（こちらが返す）／テンプレート送信／タグ付け／シナリオ開始／電話／QRリーダー。タグや回答で出し分け（セグメント）は スタンダード以上 | リッチメニュー＝スタート以上／出し分け＝スタンダード以上 |
| 流入経路分析 | 友だち追加した場所（どのLP・どのQR）を特定。**設定前からの友だちの経路は遡れない** | プロ |
| アクション管理（スケジュール） | 条件を満たした人にまとめて動作。スケジュール・定期実行はプロ | プロ |
| タグ／友だち情報／対応マーク／1:1チャット | 友だちごとの印・情報・対応状況の管理 | 全プラン |
| 予約管理（カレンダー予約） | LINE内で予約を取る。**未認識の友だちは予約画面に遷移しないことがある**（公式ブログ） | プロ（要確認） |
| CV計測・クロス分析・ファネル分析 | 配信→クリック→CVの分析 | プロ（要確認） |

## 3. 10/15〜21の疑問への答え（2026-10-21 殿村さん「これは実際どうなん？」「これもどうなん」）

- **(1) Lステップで全員向けに設定したリッチメニューは、まだLステップに入っていない人（約6,700人）にも表示されるか** → **表示される**と読む。
  根拠はLINE側の仕組み：リッチメニューの優先順位は ①ユーザーごとに設定したメニュー ②Messaging API（＝Lステップ）の全員向けメニュー ③OAMで作ったメニュー。
  Lステップの全員向けメニューはLINEが友だち全員に出すので、「Lステップがその人を知っているか」は関係しない（知らない＝Lステップの友だちリストに載っていない、だけ）。
  公式ブログも、入っていない人を入れる方法として「リッチメニュー＋自動応答」を挙げている＝出る前提の話。
  ⚠️ Lステップ側で「全員」で公開した瞬間、OAMのメニューは出なくなる（同じ画像なら見た目は変わらない）。管理画面・実機では未確認。
- **(2) 「URLを開く＋タグ付与」の枠を押した人は、友だちリストに入るか** → **入る見込み。ただし確証なし。**
  タグを付ける動作はLステップが「誰が押したか」を受け取らないと起きないので、タグ付与を足した枠は、押した人のIDがLステップに届く作りになっているはず（＝入る）。
  URLだけの枠は、LINEがそのままサイトを開いてLステップに何も届かないので入らない（解説記事に「URLリンクだと反映されません」と明記）。
  「＋タグ付与」の形が全員向けメニューでも押した人を取れるかは、管理画面でも記事でも確かめられていない。
  **確実なのは「ユーザーメッセージ送信」（押すと友だちの側から一言が送られる）。** 今のOAMのA枠（LINEで相談）はこの形なので入る。
- **決着のつけ方＝テスト1回（2本目のあと・リッチメニューをLステップで作り直すとき）**
  1. Lステップで今と同じ画像のメニューを作る（A＝ユーザーメッセージ送信／B〜F＝URLを開く＋タグ付与）
  2. 表示対象を「全員（デフォルト）」で公開
  3. **Lステップに入っていないスマホ**で、①メニューが出るか ②B〜Fのどれかを押して友だちリストに出るか・タグが付くか を見る
     （殿村さんのスマホがすでに「テスト」タグで入っているなら、入っていない社内の人のスマホで。または川本さん＝LINEOA課のLステップ担当に聞く）
  4. ②で出なければ、B〜Fも「ユーザーメッセージ送信」に変える（押すと一言が送られ、自動応答でURLを返す形）。これなら確実に入る。
- **今のOAMのリッチメニュー（2026-10-21 殿村さんのスクショ）**＝A：テキスト「LINEで相談チャットを起動する！」／B・C：`https://norst.jp/s/form_lineoa/`（1枚の画像を2マスに分けたもの・同じ飛び先で正しい）／D：`/reason/`／E：`/phimosis/surgery/`（画像は「全国院検索」・一旦そのまま）／F：`/faq/`。表示期間 2025/07/25〜2030/12/31・デフォルト表示する。
  **作り直すときは画像を変えずリンクだけ置き換える（殿村さん）。** Aはユーザーメッセージ送信のまま、B〜Fは同じURL＋タグ付与（タグ名の案＝予約フォーム／選ばれる理由／包茎手術／FAQ）。
- **エリア（都道府県）で送り分ける** → Lステップには LINE の推定属性（性別・年代・居住地）は無い。エリアで分けるには、①回答フォームで都道府県を答えてもらう（LINEログイン必須）か、②院ごとのLPを流入経路にする（新しい友だちだけ）。**今の約6,800人をエリアで分けられるのはOAMの属性フィルター（推定・3日前のデータ）だけ。**

## 4. ノーストでの使い方（10/20時点の整理）
- 配信はOAMから（Lステップに入っているのは有効90人・10/15）。**毎回の配信に「一言を送らせる」仕掛けを入れて、反応した人からLステップに入れていく。**
- Lステップに入った人＝予約に近い人。以後はLステップから、タグ（予約フォーム希望／予約済／来院済）で送り分ける・外す。
- アドアフィの計測（流入経路→予約LP→tagone）は別の仕組み。混ぜない（10/15）。
