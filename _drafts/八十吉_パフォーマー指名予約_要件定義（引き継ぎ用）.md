# 八十吉やそきち（エイトビート）LINE公式アカウント — 引き継ぎ用

最終更新：2026-09-02

佐村さん案件「親戚の会社」＝札幌の3店舗グループ。**7月に売上計上済み（100,000円・構築のみ）で、役務提供＝納品だけが残っている。**
殿村が竹田から巻き取り、川本さんが補助。

## いまの方針（2026-08-25 の店長打ち合わせで全面転換）

**外部ツールは一切使わない。LINE公式アカウントの標準機能のみで構築する。**

店長の発言がすべて：「エルメは入れたくない」「固定費は一切なし」「サイトコントローラーの活用ができないツールは導入しない」。
ただし**LINE公式アカウントへの支払いは可**（「月一万払って送れますは別に構わない」）。

**スコープも変わった。エイトビート（カラオケバー）は一旦外し、八十吉のみで作る。**
店舗開設の時期が読めないため。主役は**パフォーマー指名予約**（美容室の指名モデル）。

### 確定した道順

①お客様がぐるなび・食べログで予約＋パフォーマー指名
→ ②パフォーマーへ連絡（LINE）
→ ③パフォーマーが了承・返信（LINE）
→ ④サイトコントローラーで席を確保
→ ⑤店長へ通知（LINE）

**①④は既存の仕組み、②③⑤だけがLINE。予約の入口はLINEではない。**
席在庫を既存媒体が持ったままなのでダブルブッキングが起きず、外部ツールを足す必要がない、という論理。

### パフォーマーには八十吉のLINE公式アカウントの「操作権限」を渡す（殿村の発案）

- LINE公式の標準機能。**追加費用0円。権限の種類を問わず1アカウント100名まで**（公式確認済み）
- 2023年から**チャットルームごとに担当者を割り当てる機能**もある
- **以前ボツにした「ID共有」とは別物**＝1人1アカウントなので操作記録が残り、退職者だけ個別に外せる
- **残るリスク＝権限保持者は既存156人分を含む他のチャットも見える。**店側の了承を書面で取る前提で成立
- アカウントを2つに分ける案（顧客用／予約用）は**却下。1アカウントで進める**

### 却下した代替案

| 案 | 却下理由 |
|---|---|
| パフォーマーごとに個別アカウント | 店長が「個人でつながるのはいらない」と言っており方向が違う |
| 店舗が仲介 | 工数が残る |
| やり取り自体を減らす | パフォーマー自身に「何時で受けます」と返させたいので前提が違う |
| エルメ（L Message） | 固定費が発生する。店長の意向と真逆 |
| Lステップ | 同上。かつエルメより高い |

## 破棄したもの（2026-08-24 に作ったが方針転換で不要に）

**エルメ（L Message）フリープランでデモを構築し、予約フローが実機で通る状態まで作った。**
翌日の打ち合わせで「外部ツールは使わない」と決まったため使わない。ただし検証で得た事実は残す。

- **無料プランでも「powered by L Message」は全画面で表示されない**（トーク／予約トップ／入力／完了を実機確認）
- コースは無料でも複数作れる（セットアップ画面の「2つ以上は有料プランのみ」という表示は実態と違った）
- 有料が要るのは**オンライン決済機能のみ**
- あいさつメッセージのアクションは**「保存」を押さないと効かない**。新規友だちへのメニュー自動表示はこのアクションが担う
- システムワード変更で「コース→ご利用プラン」「スタッフ→お席」に置換できる

## この案件で効いた考え方

- **「ツールを入れない」という選択肢が存在しないことを、公式ソースで示した。**LINE公式に予約機能はなく、公式オプションの「LINEで予約」も飲食店限定かつ外部予約サービスとの契約が必須（連携先9社にホットペッパーは含まれない）。だから「入れる／入れない」ではなく「どこに入れるか」の話になる
- **店長の「サイトコントローラーの活用ができないツールは導入しない」は正しい。**複数媒体に出している飲食店で在庫を一元管理しないと必ずダブルブッキングする
- 権限付与は**ID共有とは別物**として整理すると通る。操作記録が残り、個別に剥がせる
