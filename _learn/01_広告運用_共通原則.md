# 01. 広告運用の共通原則（媒体を問わない設計思想）

> 媒体ごとの機能名は毎年変わりますが、**設計の考え方はほとんど変わりません**。
> 先にこの章を入れておくと、新しい機能が出てきても「これは既存のどれの言い換えか」で処理できます。

---

## 1. 運用の全体像 ― 順番を間違えない

```
① 目的とKPIの合意    ← ここが9割。ズレたまま走ると全部無駄になる
        ↓
② 計測設計（CV定義・タグ・GA4）  ← 配信前に必ず。後から遡って直せない
        ↓
③ アカウント構造設計   ← 予算をどう分けるか＝何を意思決定したいか
        ↓
④ クリエイティブ／キーワード準備
        ↓
⑤ 配信・学習期間      ← 触りたくなるのを我慢する期間
        ↓
⑥ 検証と改善（週次・月次）
        ↓
⑦ 報告               ← 数字の羅列ではなく「次に何をするか」を書く
```

**最頻出の事故：②を飛ばして⑤に行き、1ヶ月後に「そもそも計測できてなかった」。**
配信開始日より前に、テストCVを1件通しておくこと。

---

## 2. 計測設計 ― 配信前に必ず固める

### 決めること

| 項目 | 具体 |
|---|---|
| **何をCVとするか** | 予約完了／フォーム送信／電話タップ／資料DL。**主要CVは1つに絞る**（自動入札が迷う） |
| マイクロCVは何か | カート投入、ページ滞在、動画視聴。CV数が少ない案件では学習用に使う |
| CV値をつけるか | 売上連動ならROAS運用が可能になる。つけないとCV数最大化しかできない |
| 重複の潰し方 | 「1ユーザー1回」か「毎回」か。問い合わせは通常「1回」 |
| 計測方法 | GA4イベント／媒体タグ直／サーバーサイド（CAPI・拡張CV） |

### GA4まわりの最低限

- **キーイベント（旧コンバージョン）** に何を指定しているかを確認する
- 媒体とGA4は**数値が一致しない**のが正常（アトリビューションモデルとセッション定義が違う）。一致させようとしない
- **UTMパラメータの命名規則**を最初に決める（`utm_source` / `utm_medium` / `utm_campaign`）。途中変更は分析を壊す
- 電話CVは、電話タップ数 ≠ 実通話数。**実通話・実予約の実数と必ず突き合わせる**

### プライバシー対応（2026年時点の実務）

Cookie規制・ITP・同意管理の影響で、ブラウザ側のタグだけでは取りこぼしが出ます。
実務では **サーバーサイド計測**（Meta のコンバージョンAPI、Google の拡張コンバージョン）を併用するのが標準になりました。
「CVが落ちた」ように見えて実は計測漏れ、というケースが本当に多いので、**計測経路の冗長化**は最初に検討します。

## 3. アカウント構造 ― 「分ける」＝「別々に意思決定したい」

構造設計は美意識の問題ではなく、**予算と判断の単位を決める作業**です。

### 分ける基準（この理由がないなら分けない）

- **予算を分けて管理したい**（商材別・エリア別・季節商品）
- **目標CPA／ROASが違う**（新規獲得 と リピート、指名 と 一般）
- **停止・増減を独立して判断したい**
- **配信面や入札戦略が根本的に違う**

### 分けすぎの弊害（近年これが最大の失敗パターン）

自動入札・機械学習が主流になった結果、**細かく分けるほど1単位あたりのデータ量が減って学習が回らなくなる**。

> **原則：データが集まるまとまりを優先し、意思決定に必要な最小限だけ分ける。**
> 目安として、**1つの入札単位で週50CV**に届かない分割は、統合を検討する。

---

## 4. 自動入札と「学習期間」

### 入札戦略の系譜（媒体共通の考え方）

| 種類 | いつ使うか |
|---|---|
| クリック数の最大化 / 手動CPC | データがゼロの立ち上げ期、クリック単価を抑えたい時 |
| **コンバージョン数の最大化** | CVデータが溜まってきた段階の標準。まずはこれ |
| **目標CPA（tCPA）** | CPAを一定に保ちたい。目標が厳しすぎると配信が出なくなる |
| コンバージョン値の最大化 / **目標ROAS（tROAS）** | 売上金額を送れているEC・高単価商材 |
| インプレッションシェア目標 | 指名検索を守る、認知目的 |

### 学習期間の鉄則

- 変更後、**媒体は再学習に入る**（おおむね1〜2週間、または一定CV数まで）
- **学習中は数字が荒れる。ここで慌てて触るのが最大の失敗**
- 変更は**1度に1つ**。同時に複数変えると原因が特定できない
- 目標CPAの変更は**一度に±20%程度まで**。いきなり半分にすると配信が止まる

> 運用の格言：**「触らない勇気」**。週次で見て、月次で判断する。日次で入札を触らない。

## 5. 予算配分の考え方

### 立ち上げ期（データがない）

```
1. 確実に取れるところから：指名検索・リターゲティング（少額でCPA安）
2. 主戦場：一般キーワード検索 or Meta広告（ここに大半を張る）
3. 検証枠：新しい面・新しい訴求に 10〜20%
```

### 運用が乗ってから

- **限界CPAに収まっている経路は、原則もっと出す**（CPAを守れているなら予算は増やす方向で考える）
- **CPAが目標内なのに予算を余らせるのが一番もったいない**
- 逆に、CPAが悪い経路を「削る」判断は、**学習期間を跨いだ後**に。1週間の数字で切らない

### 予算配分でよく聞かれる質問への答え方

> Q「Google と Meta、どっちに出すべき？」
> A「**すでにニーズが顕在化しているか**で決まります。検索されている商材ならGoogle検索が最優先。
> 検索されない・知られていない商材ならMetaやデマンドジェネレーションで需要を作る側から。
> 予算が一定以上あるなら、**Googleで刈り取り／Metaで裾野を広げる**の併用が基本です。」

## 6. クリエイティブとLPは「同じ一本の線」

広告は単体で成果を出しません。**訴求の一貫性（メッセージマッチ）** が崩れるとCVRが落ちます。

```
検索キーワード／ターゲットの悩み
        ↓ 同じ言葉で
広告見出し・クリエイティブ
        ↓ 同じ言葉で
LPのファーストビュー
        ↓ 同じ言葉で
フォームの見出し・CTAボタン
```

**チェック方法：広告文のキーワードが、LPのファーストビューに出てくるか。** これだけで改善余地が見つかることが多いです。

### LP側の頻出ボトルネック（`LP分析、表.pptx` と地続き）

| 症状 | 疑うところ |
|---|---|
| 直帰が高い | ファーストビューの訴求ズレ、表示速度、スマホ崩れ |
| スクロールされるがCVしない | オファーが弱い、証拠（実績・口コミ）不足、価格の不安 |
| フォームまで来て離脱 | 入力項目が多い、必須が多い、エラー表示が不親切 |
| CVするが受注しない | ターゲットのズレ（＝広告側の問題）、フォロー体制 |

**入力項目は1つ減らすごとにCVRが上がる**のが経験則。「後で聞ける情報」はフォームから外す。

## 7. 検証と改善のリズム

| 頻度 | 見るもの | やること |
|---|---|---|
| **日次（5分）** | 消化、明らかな異常（配信停止・急増） | 事故対応のみ。**改善施策は打たない** |
| **週次（30分）** | CPA・CVR・CTR・CPMの推移、検索クエリ | 除外追加、クリエイティブ差し替え、明らかな負け要素の停止 |
| **月次（2時間）** | 目標達成度、媒体別配分、LTV・受注実数との突合 | 予算配分の見直し、構造変更、次月の仮説設定 |
| **四半期** | 戦略、ターゲット、オファー自体 | 「広告以外」を含めた提案 |

### 改善のときに使う型

```
現象（何が起きた）→ 分解（どの指標が動いた）→ 仮説（なぜ）→ 打ち手（何をする）→ 検証期間（いつ判断する）
```

例：
> 現象：CPAが8,000円→12,000円に悪化
> 分解：CPCは横ばい、**CVRが2.0%→1.3%** に低下
> 仮説：新しく追加したキーワード群の検索意図がズレている（情報収集層を拾っている）
> 打ち手：該当キーワードを別キャンペーンに隔離＋除外追加
> 検証：2週間後、CVRが1.8%以上に戻るか

**「CPAが上がったので入札を下げます」は分解を飛ばした思考。** 上の型に落としてから喋ります。

## 8. レポートの書き方

レポートは**数字の報告書ではなく、意思決定のための文書**です。

### 構成（この順番が読みやすい）

1. **結論**：目標に対して達成／未達、その主因ひとこと
2. **主要指標**：予算消化、CV、CPA（前月比・目標比）
3. **良かったこと／悪かったこと**：各2〜3点、必ず数字つき
4. **なぜそうなったか**：分解して説明
5. **来月やること**：**アクション3つ以内**、期待効果つき
6. 付録：詳細データ

### やってはいけない

- 全指標を並べただけ（読み手が結論を作る羽目になる）
- 悪化を書かない／小さく書く（信頼を一番損なう）
- 「引き続き最適化します」だけの次月施策（何もしないと同義）
